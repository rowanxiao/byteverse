## 今日概览

截至今天 09:00（UTC+8），周末的硬新闻不多，但两条线索足够看清当下的两股压力：一条来自攻击侧，一条来自物料侧。

Cloudflare 给出的数字是，一个月前公开的代理渗透框架还只有 ARTEX 一个，如今已有 50 多个家族、上万个仓库在扫它的客户，三天内来自数千个 IP；另一边，加州联邦法官驳回了三星、SK 海力士、美光对 DRAM 反垄断集体诉讼的撤案动议，起诉书里那份「DDR5 一年涨 171.8%」的账，接下来要在法庭上一条条对。

技术侧两件事值得看：OpenAI 发布了一篇把标准模型放到格点上的候选定义，由 GPT-6 Astra 参与构造证明；一位开发者用 190 行纯 JAX 重写了 DeepSeek V3 的架构，在一台 MacBook Air 上跑通训练。

国内这边，华为云把开源盘古 openPangu-2.1-Pro 上了 MaaS，价格表比参数表更值得看；前端这边 Safari 多了一个新平台——Apple HomeView，它照样上报 iOS 的 UA。

## 行业动态

- **[法官驳回三星、SK 海力士、美光的撤案动议，DRAM 涨价指控进入实体审理](https://litnews.ai/articles/garciaguirre-samsung-sk-hynix-micron-dram-conspiracy-suit-survives-dismissal)**（LitNews，11-14）

  加州北区联邦法官 Noël Wise 全面驳回三家的联合撤案动议，认定原告已就「合谋限制传统 DRAM 供应、把产能转向 HBM」提出可成立的主张。起诉书称三家在 2025 年第三季度合计掌握全球 DRAM 收入的 91% 以上，从 2022 年底开始减产，2023 年起把产能转向 HBM——每 GB 需要约 3 到 4 倍的硅片面积。

  价格数据是这条新闻的核心：起诉书称 2025 年第三季度传统 DRAM 价格同比上涨 171.8%、18 个月累计 697%，而三家均未宣布有意义的产能扩张。法官采信了这些「间接证据」：HBM 长约锁定、拒绝与传统 DRAM 客户签长约、美光 2025 年 12 月 3 日宣布关停 Crucial 消费品牌、新厂延宕，以及 2026 年 1 月起三家几乎同步的客户审查流程。

  必须说明：这些仍是未经证明的指控，法院也明确排除了另外三类论点（投资者电话会上的「供应纪律」表述、行业会议会面、寡头市场结构本身）。三家须在 12 月 7 日前答辩，案件管理会议定在 2027 年 1 月 12 日。对自建机器或采购云算力的人，这条线索解释了你最近看到的报价——HBM 挤占的是同一条产线上的晶圆。

- **[华为云上线开源盘古 openPangu-2.1-Pro，缓存命中价是输入价的五十分之一](https://www.ithome.com/1/027/450.htm)**（IT之家，11-15）

  华为云 MaaS 平台上线 openPangu-2.1-Pro，官方给的升级方向是三块：Agent 能力（基于 10 万余条专项数据优化 Skills 触发、工具选择与调用）、代码能力（面向鸿蒙 ArkTS 应用开发与昇腾算子生成）、推理链路优化（关键算子与吞吐）。它还会接进智果 AgentArts、码道 CodeArts 与果办 OfficeAce。

  价格是这条最实在的部分：输入 0.8 元/百万 tokens，输出 3.2 元/百万，缓存命中输入 0.016 元/百万。缓存价是输入价的五十分之一，意味着「固定系统提示 + 固定工具集」这类长上下文场景的成本结构会和纯按输入计费的模型差出一个量级。

  要分清的一点：这里说的是开源盘古的模型上线云服务，不是新版权重发布；具体权重、上下文长度与许可仍应以官方模型页为准，媒体稿只提供了价格与场景。对做国内合规部署的人来说，这类「国产芯片 + MaaS + 中文场景优化」的组合是可以直接拿来压成本的选项。

- **[微软 365 故障期间，德国乐园的泳池告警邮件没人看到，15 名客人氯气中毒](https://www1.wdr.de/nrw/rheinland/rhein-erft-kreis/technischer-defekt-chlor-phantasialand-100.html)**（WDR，11-14）

  11 月 13 日微软 Outlook 与 365 出现长时间故障，邮件无法送达。布吕尔 Phantasialand 乐园的桑拿区维护安全系统按设计发出了告警邮件——自动加氯系统把过多氯投进了泳池——但这封邮件没人收到，问题因此没被发现。13 名客人先反映呼吸道不适，最终受影响人数升至 15 人，4 人送医，其中 1 人因中等程度伤害留院观察。泳池一度关闭、换水后重新开放。

  这不是「AI 事故」，而是一个更常见的工程失误：把安全告警的唯一通道绑在一家外部 SaaS 的邮件系统上，且没有超时未确认的升级路径。乐园对媒体的说明是「因故障没有收到邮件」，消防部门确认了加氯系统本身的故障。

  如果你在写监控或告警，这条值得存进案例库：告警渠道要有独立于主供应商的备份（短信、电话、webhook 到另一家），并且对「已发送但无人确认」设超时升级。

- **[AI 渗透框架一个月内从 1 个变成 50 多个家族](https://blog.cloudflare.com/adapting-to-ai-penetration-testing-orchestrators/)**（Cloudflare Blog，11-13）

  Cloudflare 给出的观测：开源代理渗透框架 ARTEX 由作者于 10 月 8 日下架，此后衍生出 1.2 万多个仓库，其中数百个是带原始代码血缘的独立 fork；一个月内又冒出数百个同类编排框架。过去三天，超过 50 个框架家族在扫描 Cloudflare 的客户，来源 IP 已达数千个并继续增长；自 10 月 1 日以来，这类 AI 渗透与利用工具的日请求量涨了 30 倍。

  这些工具的能力点在于编排：接入 MCP 后把现成的扫描、枚举工具串起来，把资产映射成图，让多个并行代理同时枚举、验证、试探，速度取决于推理速度而非人力。更复杂的攻击里，它们开始链式使用窃取来的凭证做横向移动。

  需要打折看的地方：数据来自一家防御厂商，它有卖防护的动机，也没有公开原始样本。但方向与 Project Zero 上周调整披露窗口的判断一致——攻击侧的自动化程度在系统性上升。Cloudflare 提出的「现代安全模型」六条里有两条对开发者最直接：把暴露面（包括内部工具与 staging）当成会被人扫的资产，以及别再假设攻击者只有一个人工班次的速度。

- **[「AI 生成的代码应该开源」引发近 600 条讨论](https://jakub.jankiewicz.org/blog/ai-code-open-source/)**（jakub.jankiewicz.org，11-15；Hacker News 1071 分）

  作者的论证分两层。第一层是来源：模型在 GPL、CC-BY-SA 许可的代码与 Stack Overflow 内容上训练，这些许可要求署名与同等方式分发，把集体知识转成闭源专有代码等于「许可洗白」。第二层是版权：AI 生成的代码不是人写的，按美国版权局沿袭的原则（非人类不能持有版权）就不该受版权保护，而英国等司法辖区又给计算机生成作品有限保护，于是呼吁统一处理——用开源许可发布或直接 CC0 释出。

  他也划了边界：代码很少是 100% 手写或 100% 自动生成，真正该被这条规则覆盖的是「人只写了提示、连输出都没读」的那部分。

  这条更多是立场而非结论，但它指出的现实问题很硬：企业正在把大量模型输出当资产入账，而围绕这些输出的权属、审计与可追溯性，目前没有共识做法。评论区的一条反对意见值得记——强制开源会削弱企业采用意愿，最终让工具集中在少数能承担合规成本的公司手里。

- **[No AI Slop：一群工程师照着敏捷宣言的体例，写了份反 AI 垃圾宣言](https://www.slopmanifesto.com/)**（AIE Code Summit 2026 与会者，11-13 发布；Latent Space 11-14 报道）

  起草者明说体例来自 2001 年 Snowbird 那场会议：「我们更看重自己的思考，而非模型的第一稿；更看重改进系统，而非修补输出。」全文最有用的是给 slop 下的定义——**当我们投入产出的精力少于我们要求读者理解它所花的精力时，那就是 slop。**

  配套的几条判断可以直接搬进团队讨论：AI 不能替代人的判断，只能放大判断（或放大判断的缺失）；slop 是不对称的，生产千行 PR 的成本趋近于零而评审成本不变；slop 会复利，知识库、聊天记录、代码里的垃圾会被下一个 agent 读到并复制。十条决议里最可落地的三条是：凡是 linter、类型检查、自动化检查能抓的就交给它抓；同一类错误出现两次就去改系统和护栏，而不是改这一次的输出；衡量用「上线了什么、谁在用、帮到了什么」，而不是代码行数、合并 PR 数或并行 agent 数。

  宣言也留了余地——一次性提示与 vibe coding 是高杠杆工具，问题出在把未复核的输出直接转手。目前 352 个签名，签名方式是在 gist 里留言，所以它更像一份可引用的团队规范草稿，而不是标准。

## AI 技术

- **[OpenAI 与物理学家给出标准模型的格点候选定义，GPT-6 Astra 参与构造证明](https://openai.com/index/step-toward-defining-the-standard-model/)**（OpenAI，11-15；论文 arXiv 2610.09093，10 月）

  客座作者是 UCSB 理论物理组的 Nathaniel Craig。要解决的问题很老：把完整的标准模型（含弱相互作用）直接写在离散时空格点上，会因手征费米子产生「倍增子」，得到错误的粒子谱；此前只对简化理论有严格解，完整标准模型的相位规定空缺超过 25 年。他的做法是重叠费米子加一套「逐级细化」策略——把规范场表示到一系列越来越细的网格上，比较相邻网格允许的费米子态，累加出原始网格上的相位修正，并证明修正在每个允许回路上都正确。

  按文章描述，GPT-6 Astra 把策略转成了具体构造、给出搬运到细网格的方式、证明细网格比较会收敛，并主导写出详细证明；三位格点场论专家审阅并提出了关键质询。

  必须限定的部分：这是「候选」定义，作者明确说离实用模拟很远；反射正定性尚未验证，结论只在格点尺度上场强有界时成立；博客本身没有给任何数值结果，细节在预印本里，且未经同行评审。这条的意义不在物理结论，而在工作方式——人给策略、模型做构造与证明、专家做审稿，这条流水线第一次跑到了这种量级的问题上。

- **[190 行纯 JAX 重写 DeepSeek V3，在一台 MacBook Air 上训练](https://github.com/Vaibhaav-Tiwari/deepseek-v3-jax)**（GitHub，11-13 起；Hacker News 272 分）

  作者不用 Flax、不用 Equinox、不用 PyTorch，参数就是数组字典，模型每一部分都能从上读到下。190 行里塞进了 MLA（每个 token 每层缓存 480 → 144 个数）、解耦 RoPE、1 个共享专家加 16 个路由专家取 top-4、无辅助损失的偏置平衡、序列级平衡损失（α=1e-4）与多 token 预测（λ=0.3）。

  跑出来的数字很具体：36.2M 参数、每 token 激活 13.6M，207 本公版侦探小说、2170 万 token，1.2 万步约 2.6 小时（M5 / 24GB），中位吞吐约 10.7k token/s，验证损失 5.02 降到 3.51。平衡机制的效果也被量出来了：开启偏置后每专家负载 5.7%–6.9%（均匀是 6.25%），关闭后 0.09%–18.6%，而验证损失几乎一样（3.921 对 3.923）。

  作者自己列了简化项：专家全部稠密计算后把未选中的置零（无稀疏调度）、MLA 未做权重吸收、没有 FP8 与 DualPipe、上下文 256 而非 128K。这是架构教学与可复现工程，不是能用的语言模型——但这个「一台笔记本、两小时、39 个测试」的门槛，是理解 MoE 与 MLA 最便宜的方式。

- **[用 Lean 形式化整部美国税法，跑出 257 处问题](https://lexifina.com/blog/formalizing-the-us-tax-code)**（Lexifina，11-10；Hacker News 152 分）

  他们把美国法典第 26 编逐条译成 Lean——类型检查器同时是证明检查器，通过即每一步都由定义推出。法条原文取自众议院法律修订顾问办公室发布的结构化数据，版本截至 2026 年 11 月 3 日；一个解析器读取所有交叉引用，包括「第 (b) 款第 (2) 项」这类纯文字、没有超链接的写法，再由 Lean 检查指向的条款是否存在、是否仍然有效。

  检查跑成测试套件：新版本一旦引入旧版本没有的缺陷就会失败。当前报告 257 处发现；前一篇工作里，同样的盲搜重新发现了「后门 Roth」这条退休账户路径。

  这是工程记录而非同行评审论文，样本也只是一部法典。但它示范了一件对做 AI 应用的人有迁移价值的事：把「模型找问题」和「确定性检查器验证」分开——模型负责翻译与猜想，证明器负责说不，得到的结论可复现、可回归测试。

- **[The Value of Thinking：让模型自己决定这次要不要写推理](https://huggingface.co/papers/2611.16961)**（arXiv / Hugging Face，11-12）

  现有自适应推理要么压缩推理长度，要么在模式之间切换，但答案终究还是逐 token 写出来。这篇提出「零或 T 思考」：同一个模型要么靠一次前向里的隐式思考直接给答案（不产生任何 token），要么付出 T 个 token 走完整自回归推理。实现上是混合决策模型——一个冻结骨干同时服务两种模式，加一个轻量自路由块，用隐式思考已经产生的表征估计「慢模式相对快模式的预期增益」，只有增益超过每次请求设定的价格 λ 时才走慢路径。

  值得关注的原因是它把「想多久」从启发式变成可定价的决策，与 Vercel 报出的「26% 请求走决策模型、只占 0.53% 费用」是同一趋势的两端。限制也很清楚：只看摘要读不到完整的任务分布与 λ 敏感性实验，实际收益强依赖你把 λ 定得多准。

- **[Safari 登上 Apple HomeView，七英寸屏上照样上报 iOS 的 UA](https://webkit.org/blog/17613/safari-on-apple-homeview/)**（WebKit，11-14 05:00 UTC+8）

  Safari 的平台列表多了第五个成员：macOS、iOS、iPadOS、visionOS 之后，是这台 7 英寸方形屏、以语音交互为主的家居设备。WebKit 的原话是「大多数情况下你不需要做任何事」——但列出的几个假设值得自查。

  第一，HomeView 上报的也是 iOS user agent，用 UA 判断设备形态会踩坑，应该改用特性检测。第二，语音输入意味着用户是在叫按钮的名字而不是点它，语义 HTML（真 button、真 link、真表单加明确 label）、无障碍内容、大点击区、弹性布局从这里从「最佳实践」变成「可用性前提」。第三，食谱页可以从 JSON-LD 的 `Recipe` 数据生成分步烹饪视图，音视频配 WebVTT 字幕的体验也更好。

- **[Protomaps：自托管地图瓦片已经便宜到可以随手做](https://bruceroettgers.eu/blog/protomaps/)**（bruceroettgers.eu，11-15）

  PMTiles 是 Protomaps 生态里的瓦片格式：整个地图打包成单个文件，客户端通过 HTTP Range 请求按需取块。对支持大文件 Range 缓存的 CDN，上传即可用；Cloudflare 这类需要把 x/y/z 路径翻译成 Range 的，加一个边缘函数就行。只要世界地图的话，直接下载每日构建；要更小的文件，用 CLI 按边界框或缩放级别裁剪。

  成本算得很清楚：全球地图 139GB，复制到 5 个大洲约 5 美元/月的存储费；在欧洲范围内浏览并放大到一座城市，大概产生 5MB 流量。带宽按 Bunny.net 的价目是 0.01 美元/GB（小流量网络 0.005）。对比之下，Mapbox 在免费额度用完后按每千次加载 5 美元计费——对一个可能会爆火的小项目，这个差别是生与死。

  适合的场景很明确：静态地图、数据可视化、内网工具、离线包。不适合需要实时路况、地理编码、路径规划的产品，那些仍要接商业服务。

- **[Kiri：用一个 daemon 跑容器的桌面替代品](https://runkiri.com/)**（官网，Hacker News 11-15 讨论）

  定位是 Docker Desktop 的轻量替代：CLI、Compose、Docker API 按原样工作，底层是单一 daemon。作者给的启动数据是 22ms，对照 Docker Desktop 178ms、Colima 152ms、OrbStack 279ms，测试条件是 2 vCPU / 8GB 且同一时间只跑一个运行时。除容器外还带镜像构建与漏洞扫描、约 20 秒起的 k3s 集群、`kiri machine create` 生成 Linux 虚拟机、一键把容器挂到公网（自带窄用途 CA 签 HTTPS）。空闲后虚拟机休眠，daemon 约 15MB，唤醒 0.15 秒，并支持从 OrbStack 或 Docker Desktop 迁移镜像与卷。

  对你的用途：本地要同时跑 Postgres、Redis 加几个服务时，Docker Desktop 的体积与授权是长期痛点，这类替代品值得放进候选。两点打折：性能数字全部来自作者自测、没有第三方复现；免费 beta 不等于长期定价承诺。
