## 今日概览

截至今天 08:55（UTC+8）。Anthropic 昨晚完成纳斯达克首日交易：开盘 111.50 美元、收盘 97.17 美元，较 83 美元的发行价涨 17%，完全稀释市值约 1.8 万亿美元。但这次史上最大 IPO 没能带起板块，纳指当天跌 2.25%，标普 500 连续第六个交易日下跌。

安全侧是今天更该处理的事。Ruby 的 `ruby2shell` 用单字节堆溢出打通了未授权 RCE，Rails 与 Sinatra 在默认配置下就可被攻击，GitLab、GitHub Enterprise Server 目前都没有修复版本。

AI 侧两条偏研究：Claude 用一组 agent 解出两个悬了二十多年的黑洞物理问题并在 Lean 中形式化验证；OpenAI 公布模型改芯片的实际收益，AMD GPU 上拿到最高 14% 的 PPA 改进。

- **[Quad9 将于 11 月 24 日停止响应来自法国的 DNS 查询](https://techstackups.com/articles/quad9-leaves-france-dns-blocking/)**（Tech Stack Ups，11-18；讨论见 [Hacker News](https://news.ycombinator.com/item?id=50545958)）

  巴黎法院 10 月 21 日判决，因 Quad9 拒绝为 beIN Sports 屏蔽 58 个盗版体育直播域名，处以每天 1,000 欧元罚款、持续到 11 月 14 日 WTA 赛季结束，合计约 2.4 万欧元。Quad9 说还有约 20 起同类案件待审，按这个罚法撑不下去，于是选择退出而不是全球屏蔽。

  法律依据是《体育法典》L.333-10 条，2021 年立法时把「任何能帮助制止侵权的人」都写进管辖范围——这句话把 DNS 解析器也算进去了。2026 年 7 月的新法又加了由 Arcom 运营的自动化实时屏蔽，Quad9 称其「recklessly dangerous」。

  之所以值得你花时间读，是它把「DNS 层拦截」的代价摊开了：DNS 不含内容，只传指针；Arcom 自己的研究显示 20% 的法国网民已改用替代解析器、29% 用 VPN；意大利 Piracy Shield 在 2024 年误封过 Google Drive，RIPE Labs 统计到 500 多个无关站点被波及；欧盟委员会 2025 年的评估结论是效果「有限」。连锁反应已经在发生——Cisco OpenDNS 2024 年 6 月撤出法国、2025 年 4 月撤出比利时，意大利 2026 年 1 月对 Cloudflare 罚了 1,420 万欧元。

  对做海外业务的人是实际风险：如果你的产品依赖公共 DNS、CDN 或 VPN 出口，法国模式一旦被欧盟采纳为模板（欧洲议会法务委员会委托的研究已在提议 30 分钟内强制屏蔽的法规），可用的解析器会变少，而「用户打不开」这件事将越来越难归因。

## AI 技术

- **[Claude 解出两个黑洞物理开放问题，结果在 Lean 中通过形式化验证](https://www.anthropic.com/research/claude-black-hole-physics)**（Anthropic Research，11-17）

  第一个是 1983 年 Hawking-Page 相变的性质：低温是粒子气体、高温是黑洞，这个切换到底是突变还是渐变？2003 年有人提出过判定方法，但计算极其复杂，二十年没人做完。Claude 做到了三圈修正（数千个费曼图）并给出答案：是突变。

  第二个是 3D 引力的模 bootstrap 上限。此前解析证明只能压到 c/8.5，数值结果暗示能到 c/9.1 左右。Claude 从数值里看出物理学家漏掉的规律，引入谱曲线（spectral curve）这个来自其他领域的工具，证明最轻黑洞质量不超过 c/9.1266，且这个上限对该方法是**最优**的。

  过程比结论更有信息量：8 月研究员让它列开放问题，它几小时给了 22 个候选；每个问题配一个 agent，互相能读到对方的进展，在后台跑了约六周；几乎每步计算都由独立 agent 做了两遍，另有两个 agent 独立得到同一答案；9 月在 Lean 里完成形式化验证；论文由 Claude 起草、物理学家逐条核对主要结果。

  限制作者自己写清楚了：两个结果都不直接描述我们的宇宙，也没有实用价值；都没解决量子引力的核心问题；Hawking-Page 那条只证明了「最自然的可能性」，不是严格的全耦合证明。值得学的不是「模型能搞物理」，而是这套配置——多 agent 冗余计算 + 形式化验证 + 人类只做终检——能不能搬到你的领域里。

- **[OpenAI 公布模型改芯片的实测收益：AMD GPU 上最高 14% 的 PPA 改进](https://openai.com/index/advancing-chip-design-with-our-models/)**（OpenAI，11-18）

  三块内容。自研推理芯片 Jalapeño：向量单元标准单元面积减少约 13%、矩阵单元约 10%，其中一处乘法器重设计省 15% 面积同时把延迟从两个时钟周期降到一，这些优化在流片点亮时已获硅验证。与 AMD 合作：在旗舰 GPU IP 上相对「已高度优化的基线」拿到最高 14% 的 PPA 改进，官方称相当于不到 5 个月做完约一年的进度，部分改动已进入送厂版本。

  评测部分值得看方法：用 PicoRV32 与 OpenTitan 里的 Ibex 两款开源 32 位 RISC-V 核，9,881 次计分运行，分数 = 隐藏负载上的每时钟指令数几何均值 × Yosys 估算的最高频率，面积不得超过原始 16 倍。GPT-6.2 Astra 在两款核上平均分最高，PicoRV32 上约为 GPT-6 Astra 的两倍。

  原文自己承认了一个偏差：从规格重新设计时，模型可以省掉原核的性能计数器、额外指令等特性，而这些对测试负载吞吐影响很小——这能解释一部分分数优势。要贴近生产，需要强制包含这些特性、收紧面积上限、并在物理综合后查时序。

  下一步是与 Synopsys 联合训练 GPT-Synopsys，让模型「像专家那样用 EDA 工具」。这条对非芯片行业的读者也不是无关：它示范了「模型 + 领域工具 + 严格评测」这个组合怎么在硬指标领域落地。

- **[DaisyRose-27B：1,200 个任务、18 天、144 张 H200，Terminal-Bench 从 5.6% 提到 12.0%](https://www.radixark.com/blog/daisyrose-27b)**（RadixArk，11-18；[权重](https://huggingface.co/RadixArk/DaisyRose-27B)）

  基于 Qwen3.8-27B 做强化学习后训练，用自家开源框架 Miles。数据是与 Eigent AI 合作从数千候选里筛出的约 1,200 个任务，筛选标准很硬：每个任务必须针对原模型真实会犯的错、必须由多个相互依赖的子问题串成长任务（单次最多 1.5 小时、100+ 次工具调用、256k 输出 token）、且必须人工复核过「不能不真正解决就通过」。

  工程数字比榜单更有参考价值：训练用全异步模式，128 张 H200 跑 agent 推理、16 张跑训练器，互不等待；MFU 37%，对照的开源 Megatron 训练器在同类任务是 16%，等于省 57% GPU 时间（MoE 模型上差距更大，Qwen3.6-35B-A3B 上 6.2 倍）；用于训练的沙箱服务九周跑了约 94.4 万个沙箱、峰值 1,566 个并发，99% 创建成功，成本比常见云沙箱方案低约 80%。

  限制照实说：Terminal-Bench 4.1 用自家 mini-swe-agent harness 取 8 次平均，换 harness 数字会变；1,200 个任务规模很小，泛化能力未经检验。BF16 / FP8 / NVFP4 三份权重都在 Hugging Face 上，想复现「小数据 + 好基建」这条路线的可以直接拉。

## 大前端与后端

- **[ruby2shell：一个字节的堆溢出，Rails 默认配置下就能未授权 RCE](https://verialabs.com/ruby2shell/)**（Veria Labs，11-18；[Ruby 官方公告](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)）

  编号 CVE-2026-132825，评级 critical。根因是 Ruby 大多单字节编码里没有大写 `ß`：`upcase` 时它要写两个字节 `SS`，但循环的边界检查只算了一个（`to < to_end`），输出缓冲区按「输入长度 + 20」分配，输入里放 21 个 `ß` 就溢出 1 字节。写入的是 `S`（0x53）或 `s`（0x73），落点紧跟在缓冲区之后，而缓冲区大小由攻击者的输入长度控制，把结果拷出来时再越界读 1 字节。

  触发面：`upcase`、`swapcase`、`downcase(:fold)`、`casecmp?`。UTF-8 走另一条代码路径，不受影响。Rails 与经典风格的 Sinatra 在**默认配置**下可达，其他框架与裸 Rack 默认不暴露，但应用代码如果对 legacy 编码的入参做了大小写转换，同样中招。这个循环从 Ruby 2.4.0 就在了。

  修复版本：Ruby 3.3.14、3.4.13、4.0.10（3.2 及更早已 EOL，没有补丁）。自托管产品要等厂商：GitLab 19.6.0 及更早、GitHub Enterprise Server 3.22.5 及更早、Chatwoot 4.20.0 及更早**目前都没有修复版本**；Mastodon 4.7.6 / 4.6.12 / 4.5.22 / 4.4.29、OpenProject 17.9.8 / 17.8.3、Discourse 镜像 2.0.20261119-0203 已修。

  Veria Labs 说会在 11 月 25 日公布在 stock Rails 上打通 RCE 的 PoC，若大厂届时仍未发版则推迟。跑 Rails 的服务今天就该升级；升不了的话，把对外入参一律按 UTF-8 处理并拒绝非 UTF-8 编码，能挡掉这条路径。

  语言层最实用的是偏函数应用：用 `?` 和 `...` 占位，先绑一部分参数、返回一个 Closure 等剩下的，少写一层箭头函数。另有 `\Time\Duration`（与时区无关的经过时间，纳秒精度、可跨 250 年）、`clamp()`、`SortDirection` 枚举、只读属性可带默认值、参数级 DocComment（不再写 `@param`）。

- **[在一台 10GB / 1 核的 VM 上跑 1,600 万个 Web 服务器](https://kapteko.com/15-million-webservers/)**（Kapteko，11-19）

  过程是一次典型的「撞墙 → 换层」。最朴素的 C 服务器能到 65k RPS，但跑 1,500 万进程会撞端口上限（`u16`，约 65k），要靠多 IP 或 IPv6 子网绕开；改成单进程自定义运行时后，每个 guest 只需存 16 字节上下文（1,500 万个约 220MB），却在实测时 OOM——因为内核里每次 `socket()` 要占约 3,300 字节（`tcp_sock` 2,240 + `socket_alloc` 768 + `file` 184 + `dentry` 192），这条路径无法小修小补，堆到约 250 万就耗尽内存。

  解法是把网络栈搬到用户态：用 Rust 的 smoltcp（独立、事件驱动、完全不需要堆分配）替换内核栈，运行时截获 guest 的 syscall 转给它；对接网卡有三条路——TUN/TAP 不过内核、DPDK 完全旁路、AF_XDP 部分旁路。结果是空闲服务器降到 620 字节、活跃约 1KB，1,600 万跑通。

  代价写得很实在：DPDK 一开，网卡就从 OS 里消失，`ifconfig` 看不到、SSH 会断；忙轮询吃掉一整个核。作者也反思了自己一开始轻信「空闲连接占 0 内存」的说法。真正的难点不在 PoC，而在完整 POSIX 兼容的运行时——那需要另一篇文章。

  作者 32GB 的机器被「并行开太多东西」吃满，解法是 zram 而不是买内存。他用脚本在 Firefox 里连开约 100 个站点，实测 5.7GB 数据压进 1.7GB 物理内存，压缩比 1:3.35；代价是一点 CPU 和部分进程的延迟。
