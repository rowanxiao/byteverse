## 今日概览

截至今天 09:00（UTC+8），过去两天的主线是「故障与供应链」。

微软把 11 月 12 日到 13 日那场持续两天的 365 故障归因到 7 月的一个补丁：网关服务器里的锁竞争，在 Teams 切流加 14% 容量下线的情况下，把八成以上机器打到失联。同一天，Optimizely 的客户自定义脚本被写入恶意代码，178 家企业的 188 个 snippet 被污染，名单里有 Zoom、BBC、GitLab、汇丰。

模型侧，阿里发布 Qwen4-Max：2.4T 总参数、百万上下文、权重不开源，只走 API；DeepSeek 把 App 里的联网搜索、文件解析、语音识别拆成独立接口对外开放。前端今天有硬货：WebKit 放出了空间 CSS 的开发者预览，uBlock Origin 则曝出一个靠一次点击就能注入通用 XSS 的漏洞。

## 行业动态

- **[微软公布 365 两日故障初步复盘：七月补丁里的锁竞争，八成网关失联](https://www.zdnet.com/business/microsoft-outage-outlook-teams-copilot)**（ZDNET，11-16）

  微软通过 365 管理中心发布初步事故报告（事件号 EX1550543 / MO1550821），Copilot 与平台业务 EVP Charles Lamanna 在 X 上给了公开摘要。三个条件叠在一起：7 月为 365 网络网关服务器专门准备的一个修复里有锁竞争，特定负载下进程被拖到不可响应；故障前约 15 小时 Teams 从备用网关切到同时承载 Exchange Online 的主网关；前一天另一个故障让约 14% 的网关容量下线。

  两小时内，这个此前未暴露的缺陷扩散到整个机群，最低谷时八成以上服务器无响应。流量管理把用户导向健康节点，反而让同一缺陷在剩余机器上更容易触发；本该把故障限制在分区内的隔离机制也没起作用，本地问题变成全球问题。恢复同样不顺：机器一上线就被积压流量打回，自动化恢复流程没按「大面积同时失效」设计；改动已是几个月前的事无法回滚，工程师只能分组把代码路径还原到旧的已知状态。

  最该记的是测试那一段：微软承认压测偏向核数更少的弱机型，而这个缺陷在高核新机器上更严重。Teams、OneDrive、SharePoint 能绕开故障网关先行恢复，Exchange Online 因为体量原因不能，所以邮箱停得最久。最终报告定在 11 月 20 日。

- **[Optimizely 的客户脚本被注入，178 家企业的 188 个 snippet 中招](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)**（Report URI，11-16）

  Optimizely Web 的工作方式是每个客户从它的 CDN 加载一段 snippet，snippet 里除了实验配置，还有客户自己在后台写的「Project JavaScript」，这段代码会在每个页面执行。攻击者把代码写进了多家客户的这段字段，文件本身仍从 `cdn.optimizely.com` 发出、带 Optimizely 的证书——对已经信任该域名的站点来说，这就是第一方脚本。19:52 UTC 时 188 个 snippet（属 178 个组织）中还有 1 个（TalkTalk）没清干净，20:56 时是 169 个。

  注入的载荷是多用途的：替换页面与剪贴板里的加密货币地址（BTC、ETH、TRON、Solana 等，做了校验和验证），监听表单提交与 XHR 抓卡号、有效期、CVV，用 html2canvas 截图，并在 iOS 18.6 及更早版本上加载一套利用链。托管支付 iframe（Stripe、Adyen 一类）里的卡号拿不到，站点自己表单里的能拿到。

  报告明确说这不是 CDN 缓存投毒，攻击者是怎么拿到这么多互不相关项目的写权限仍未解释。对做前端的直接含义：第三方标签管理器的「自定义 JS」字段等于你自己站点的 XSS 入口，CSP 用报告模式而不是执行模式，在这种情况下只能事后知道。

  官方公布的国内定价口径是缓存命中每百万 token 0.5 元，单任务平均费用比上代降约六成；海外站点价格以阿里云百炼控制台为准。能力侧，CodeArena 前端编程盲测第 6（官方称在中国模型中最好），Agents’ Last Exam 46.7、比上代高 18.8 分，Work360 全场景 52.69。

- **[代理已经是用户了，所以你的软件需要 eval](https://vercel.com/blog/agent-evals)**（Vercel Blog，11-16）

  这篇是目前少见的、把「怎么给代理写测试」讲成流程的文章。它先给了一个金字塔：确定性测试（0 次模型调用，验 API 行为）、单轮 eval（1 次，验是否选对命令与参数）、端到端 eval（2 次以上，验整条任务成不成），原则是从你想抓的问题出发，选能抓住它的最低层。

  指标部分最有用：5 次试验通过 3 次，成功率 60%，Pass@5 约 99%，Pass^5 约 8%。选哪个取决于失败的代价——点咖啡要 Pass^k（每次都成），带测试套件的编码代理可以重试，用 Pass@k；成本要算进失败次数（示例里单次成功 0.56 美元，计入失败后每次 0.78 美元）。

  工程细节也给了：任务目录里放指令、环境 Dockerfile、校验器、标准答案；环境要冻结时钟、保护种子数据，防止代理直接改 `orders.json` 骗过校验器；示例 job 是 4 个任务 × 4 个配置 × 5 次 = 80 个 trial，用 Harbor 在沙箱里跑，再派一组便宜模型并行读轨迹找根因。文末还附了一段可以直接粘给编码代理的提示词。

- **[Lean 说「检查通过」不等于定理正确，这位数学家给了四个必答问题](https://xenaproject.wordpress.com/2026/11/12/and-the-proof-is-checked-in-lean/)**（Xena Project，11-12；Hacker News 11-16 讨论）

  Kevin Buzzard 针对「这个定理在 Lean 里检查过」这类说法写了篇辨析。背景是一批 722 篇的数学论文，其中约 45% 附带 Lean 代码，而三篇没有形式化的论文后来因符号错误被撤稿——于是「有 Lean 就一定对」和「Lean 也能被 hack，所以没意义」两种说法同时流行。

  他给的检查清单是四问：Lean 里的陈述和论文里的定理陈述是不是同一个（他举了 Axiom 关于有限单群分类的证明，陈述所在的文件导入 25 万行 AI 生成的 Tau Ceti 代码，其中 5600 行是定义）；代码能不能编译（Anthropic 那次费马大定理给了 1300 万行，需要 96 核、500GB 内存才编得动）；证明是不是真的证明了那个陈述（要工具比对可信陈述与不可信导入，且只用数学公理）；有没有利用 Lean 内核的健全性 bug（好在 Lean 有多个独立内核，可以交叉验证）。

  文章里还有个刺人的统计：290 个带 Lean 代码的 OpenAI 定理中，约 38 个的代码根本没陈述论文的主定理——OpenAI 也从没这么声称。对做「模型找问题 + 证明器验证」这条流水线的人，这篇是把「verified」这个词拆开看的最好材料。

- **[Aristotle 开始验证 Rust：证明没有未定义行为，也能证明重写前后等价](https://www.harmonic.fun/news/aristotle-rust-verification/)**（Harmonic，11-16）

  Aristotle 原先做 C 与 Verilog 的形式化验证，现在扩到 Rust：可以证明代码没有未定义行为、符合规格说明，包括在 `unsafe` 块内；如果是从 C 重写成 Rust，还能证明新代码与原实现行为一致（翻译验证）。同时宣布与 Solana 基金会合作，支持链上程序的验证。

  厂商给的案例有两个：一个开源订单簿项目里证了 28 条性质，并发现一处取整 bug（团队已修）；一家主经纪商业务里证了存取、借贷、还款、清算任意顺序下账本一致。

  要打折看的地方：这是厂商自述的案例，没有第三方复现，也没有公开的价格与吞吐数据（只写按量洽谈）。但它代表的方向值得跟：把「测试覆盖不到的部分」交给证明器，正在从学术演示变成按行计费的商业服务。

## 大前端与后端

- **[WebKit 放出空间 CSS 开发者预览：用声明式 CSS 摆放 3D 物体](https://webkit.org/blog/18621/introducing-spatial-css-a-developer-preview/)**（WebKit，11-17 07:45）

  visionOS 27.3 里带了一个受限的特性预览，实现的是提案中的空间 CSS，重点在 `<model>` 元素——这个元素在 Safari 27 上已经全平台可用。核心变化是让容器声明自己是「传送门」（`spatial: portal`），子元素共享同一个 3D 空间，然后用普通的 `transform` 做平移、旋转、缩放，数值照常可以参与动画与过渡。

  几个细节值得记：模型不能互相嵌套，所以定位借用了 CSS 锚点，用 `position-anchor` 指向 3D 编辑器里预先摆好的空物体（Blender 里的 null object），省掉手抄坐标；环境光照从 HTML 属性升级成 `@environment-map` 声明，支持 360° HDR；`portal-action: orbit` 让用户绕场景旋转；另有 `requestVolumetricScene()` 把内容从浏览器窗口里拿出来，放进用户空间的「连通体积场景」，页面与场景保持实时联动。

  意义不在立刻可用，而在方法：3D 交互不再靠 JS 维护一整套状态机，而是复用媒体查询、过渡、锚点这些已有概念。目前仅 visionOS 预览，桌面与移动端没有时间表。

- **[uBlock Origin 的通用 XSS：点一下就能让任意站点执行你的脚本](https://iter.ca/post/ubo-uxss/)**（iter.ca，11-15；公告 GHSA-cmqw-9r2w-6wv2）

  漏洞在元素选择器（element picker）。作者发现三件事可以串起来：Firefox 上扩展的内部 UUID 会通过 `no-fetch-if` 这条默认过滤规则里的 XHR 泄给页面；选择器 UI 是个可通过 `moz-extension://` 直接 iframe 的页面；它接受任意来源的 `postMessage`，而消息里的 `opt` 字段会被拼进过滤规则。于是给 `opt` 里塞一个换行，就能追加一条 `##+js(...)` 的「可信」脚本规则，在任意域名上执行任意 JS；再用透明度为 0 的 iframe 盖住按钮骗取点击即可。

  影响范围：uBlock Origin 1.75.2 及更早，修复在 1.75.4，公告评级 high，11-15 发布。修复方式之一就是给选择器加一个只有内容脚本知道的口令，不再接受陌生人消息。uBO Lite 有类似但危害较小的问题。

  两个可迁移的经验：能注入脚本的「可信」通道一旦被页面驱动，就等于把 XSS 做成了产品功能；发现过程里 GPT-5.6 Sol 找到了主要问题，作者负责验证与写 PoC——这类扩展的攻击面审计，已经是模型擅长的活。

- **[Jiff 1.0：Rust 的日期时间库承诺长期稳定](https://burntsushi.net/jiff/)**（burntsushi.net，11-15）

  Andrew Gallant 发布 Jiff 1.0，并明确说除非发现重大 API 缺陷，否则会长期停在 1.0——理由是这个库要成为被别人公开 API 引用的基础设施，频繁的不兼容升级会顺着依赖树传播。它已在 uv、Cargo、Starship、fd、Nushell、mise、Jujutsu 等项目的生产环境里使用。

  设计取向是把时区与 DST 放在正中央，而不是当附加功能：默认不给你一个「没有时区的时间戳」，把「哪个时间、哪个时区、什么规则」拆成不同类型，让容易出错的写法在编译期就过不去。文章本身就是一篇 API 导览，从 `Timestamp`、`Zoned` 讲到跨度运算与格式化。

  对后端与工具链开发者，这条的现实意义是选型：如果你的项目里有一堆 `chrono` 时代留下的时区补丁，Jiff 1.0 是个可以考虑的迁移目标；但如果你的 API 已经把 `chrono` 类型暴露出去，迁移成本要单独算。

- **[clice v1.0：一个完全用 C++23 重写的 C++ 语言服务器](https://ykiko.me/en/articles/2105384023094834022/)**（ykiko 的博客，11-15）

  作者从零重写了一个基于 LLVM/Clang 的语言服务器，目标是修掉 clangd 与 ccls 里多年未解的结构性问题。实现上用了 C++20/23 的模块、concepts、协程（自研基于 libuv 的结构化并发库），编译放进进程池而不是线程池（理由是 C++ 编译器本身状态重，多进程隔离更稳），构建用 Bazel 做到可复现，二进制开了 PGO 与 LTO。

  成熟度给的也算诚实：7 月 19 日起发 nightly，约四个月 alpha，靠真实开源项目跑出的问题清单收敛，到 1000 次提交才发 1.0。

  对写 C++ 的人，这是个可以直接替换 clangd 的候选，尤其在大型仓与模块化项目上；对不写 C++ 的人，这篇是「现代 C++ 到底能不能用于复杂软件」的一份实证——作者自己承认，语言特性够用，周边生态（包管理、模块包装、工具链）仍然很痛。

- **[OpenCode Browse：让代理用你正在用的那个浏览器](https://opencode.ai/product/browse)**（OpenCode，11-16）

  它由两部分组成：一个 MCP 服务器加一个 Chromium 扩展。代理打开的是你真实的浏览器会话，带着你已登录的站点、Cookie 和扩展；新标签在后台以折叠分组打开，可以读页面、点击、输入、截图、录屏，还能看网络请求。

  设计上有个聪明的退让：遇到登录、2FA、支付这类不该由代理代劳的步骤，它把标签交回给你，你点「继续」之后代理接着跑。支持 Chrome、Edge、Brave、Arc、Helium、Vivaldi、Opera，客户端侧兼容 OpenCode、Claude Code、Cursor、Codex、Zed，一条 `npm install -g @opencode/browse` 就能装。

  和 Playwright 那类无头方案相比，它的优势是「不用重新登录」——内部系统、双因子、企业 SSO 这些最麻烦的前置条件直接省掉；代价是代理与你的日常浏览共用一个身份，权限边界要靠域名白名单自己划。
