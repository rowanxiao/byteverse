## 今日概览

截至今天 17:50（UTC+8）。今天最值得读的不是新模型，而是一份安全研究：Dragos 在七到十一月投放了近 200 万条带唯一追踪标记的提示词，观察它们离开推理链路之后去了哪里，结果是三家推理服务商被入侵、市场卖家能直接读客户提示词、隐私开关被无视；OpenRouter 今天回应，清退三家供应商并撤掉 125 个端点的零留存资格。

今天的另一条主线同样重要：Lean 与 Mathlib 社区用一天时间独立核验了 Alpöge 的黎曼猜想证明，形式化验证第一次成为 AI 数学产出的验收流程。

工程侧今天有两篇值得慢读：Pinterest 与英特尔把开源连续性能分析器 gProfiler 推到超大规模生产环境，OpenAI 则公开了 Codex 沙箱的权限分层设计。

## 行业动态

- **[Dragos 投放 200 万条提示词，发现三家推理服务商的数据被窃](https://www.dragos.com/blog/ai-supply-chain-security-canary-tokens)**（Dragos，11-19；[OpenRouter 回应](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/)，11-22）

  研究团队在 7 月至 11 月间，向多家主流 AI 服务提交约 200 万条含唯一 URL 与 canary 凭据的提示词，然后监控这些标记是否被访问。三个结论一个比一个难看：三家托管商的推理流量被攻击者实时复制，最严重的一次是几百个 AWS 密钥在十月底的几个时间窗内全部被偷，连模型还没跑就被拒的请求也在其中，说明复制点在前门而不是推理栈深处；推理市场里的小卖家只要把某个模型挂到最低价、打开请求日志，就能读到流经的提示词；还有服务商无视客户设的"不收集/零留存"开关，中国某实验室的系统访问了他们七月至十月发出的一半以上提示词里的密钥 URL，其中约三分之二请求标着零留存。

  最刺眼的一条细节：一条提示词里的链接，在请求发出 24 天后被贴进了飞书群，两分钟内从北京、上海的六台设备打开——而研究者披露时只给了链接前八个字符，说明对方读的是完整存档。

  对做 AI 应用的人，结论不是"换一家供应商"。提示词里塞着源码、内部文档、数据库连接串和云密钥，而每多经过一层路由、转售和区域节点，就多一个能看见全文的对手。可落地的动作：把密钥与个人信息从 prompt 里剔除或做占位替换；对需要保密的链路直接签供应商协议而不是走聚合平台；评估 prompt 日志的留存策略；以及假设"零留存"是合同条款而不是技术事实。

- **[OpenRouter 清退三家供应商，撤掉 125 个端点的零留存资格](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/)**（OpenRouter 公告，11-22）

  公告确认自身没有被入侵，问题出在上游：三家供应商被下架，125 个端点从零留存（ZDR）名单里移除——既有被研究者点名的，也有出于谨慎一并撤掉的；所有可能受影响的客户已收到邮件通知。后续动作包括把研究者的测试方法产品化、定期跑；对网络路径做技术核查，看请求是否被转发给第三方；以及要求供应商提供保证与验证后才恢复 ZDR 资格。公告同时挂出了两条相关事件链接：Novita 上 MiniMax 请求的隐私通告，以及 2026 年 6 至 7 月请求的提示词泄漏事件。

  公告没有点名三家供应商是谁，HN 上有人据自己收到的邮件与目录变动推测是 Atlas Cloud、Novita 与 Streamlake，未获官方确认，只能当社区说法看。讨论里另一条共识更值得记：ZDR 是承诺而非机制，真正可验证的只有自建推理或带可信执行环境的方案；有人反问"重新声明一遍就等于审计过了吗"，这个问题目前没人能正面回答。

- **[Lean 与 Mathlib 社区认证黎曼猜想证明，四条标准逐条公开](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)**（Lean community blog，11-21；[核验材料](https://math.mit.edu/~drew/grh/)）

  11 月 20 日 Levent Alpöge 发布约 1700 万行的 Lean 库，声称证明了黎曼猜想；次日 13:55，Lean 与 Mathlib 社区发布联合声明，确认四条标准全部满足：所证命题就是 Mathlib 里的 `RiemannHypothesis` 定义、整个库可编译且多人复现同一份导出文件、两个独立工具比对确认命题一致、导出的证明被 Lean 官方内核与若干独立检查器验过。

  关键在于这些检查跑在一份"惰性"导出文件上，接触不到源文件里可能存在的恶意代码；检查器自身还带一份相对于集合论的形式化证明，说明它们不会接受假证明。这次不只是"AI 做出了数学"，而是第一次有一套可复现、可外包给陌生人的验收流程——评审成本从"读完证明"降到"跑检查器"。边界也要说清：检查器只保证证明与命题一致，不判断命题是否重要。

## 产品发布与更新

- **[Ulika：给 AI 生成的站点加一层可视化编辑器](https://www.producthunt.com/products/ulika)**（Product Hunt，11-22，开放公测）

  它盯的是一个很具体的工作流裂缝：用 Claude Code、Cursor、Codex 一个周末就把 React / Vite / Next 站点做完了，然后市场同事想改一句标题，只能开工单。Ulika 通过连 GitHub 与 Vercel 识别项目，让非工程角色直接在页面上改文案和图片并发布，不需要迁到 CMS。作者是墨西哥城的产品设计师，自己在评论区说"已经有真实站点在用，onboarding 还在打磨"。

  对你这类既写代码又要交付客户站点的人，它省掉的是"每次改文案都要走一遍 PR"的摩擦；但要接受两点：一是编辑范围限于文案与图片，不是完整的内容模型；二是它要读你的仓库与 Vercel 项目，权限边界得先看清。当前是开放公测、免费可试；官网为纯前端渲染，静态抓取没取到内容，功能与价格以发布页和 maker 自述为准。

- **[Omi CLI：终端里的编码 agent，13 个模型自动切换](https://www.producthunt.com/products/omi-cli)**（Product Hunt，11-22；[官网](https://cli.builditomi.com)）

  交互形态和 Claude Code、Codex CLI 近似：读仓库、出计划、每处改动以 diff 呈给你确认、跑测试直到通过。差异在模型调度——按每一轮任务的难度从 13 个模型（DeepSeek、Gemini、Gemma、gpt-oss、GLM 等）里自动挑，官方说法是日常小改走便宜模型、难题升级；`/undo` 不依赖 git 也能回滚上一次任务改过的所有文件。

  安装是一行 `npm i -g @builditomi/cli`，有免费档，付费是单一 USD 套餐、按 5 小时与每周限额计费。官方给出的首个公开基准是 10 个小任务全通过，样本很小，且判分用的是 agent 没见过的隐藏测试——可以当参考，不能当结论。适合已经在用多个模型、想统一账单的人试；单看编码能力，它还没有与主流 CLI 拉开差距的证据。

- **[Entire：把 PR 换成"评分轨迹"的 Git 托管平台](https://www.infoq.cn/article/6swrOq5xUXwVqrREwJwc)**（InfoQ 中文，11-21；[官网](https://entire.io)）

  创始人 Thomas Dohmke 是前 GitHub CEO，判断传统 PR 流程不适合多个 agent 高频迭代。Entire 的做法是 trails：每次推送后，云沙箱里的评审 agent 给出置信度、风险、slop、测试覆盖等分数，界面置顶展示最近 5 轮结果，开发者按 gates 判断继续迭代还是合并；所有发现的问题必须解决或关闭才能合。配套的 continuous memory 把代码图谱、历史会话与 Git 记录存进仓库，供后续 agent 复用"为什么改"的上下文。

  当前是 early access，按用量付费：代码托管、trails、会话存储、记忆、CLI 免费，评审 agent 按模型厂商公开价格计费。需要权衡的是迁移成本与分数可信度——评估规则由你写，分数好坏取决于规则质量。

- **[gitroots：给 GitHub 加路径级权限，人和 agent 同一套审批](https://www.producthunt.com/products/gitroots)**（Product Hunt，11-21）

  场景来自外包团队：想让某人只改一个模块，结果不得不把整个仓库给他。gitroots 在 GitHub 之上做一层治理：按人、团队或 agent 设定可访问路径，读写权限分开，越界改动变成待审批的同步请求，网页、手机或 CLI 都能批，读操作也进审计；Claude Code、Codex 走的是和人一样的检查。

  Starter 免费，付费 19 美元/月起，目前只支持 GitHub。作者在评论区承认了一个硬限制：同步进目标仓库的提交不再保留原作者的 Verified 签名，而是记在 gitroots ops 名下——对要求签名可验证的团队，这条足以否掉方案。

- **[LookAtMyQuant：把 Inkling-2-Mini 压到 5.4 GB，并给出每档的掉分曲线](https://github.com/ShinMegamiBoson/lookatmyquant)**（GitHub，11-21）

## 大前端与后端

- **[Pinterest 联合英特尔把开源性能分析器 gProfiler 推到超大规模生产](https://www.infoq.cn/article/fs4IuBTjwIwR1xUgdjqt)**（InfoQ 中文，11-22；原报道见 [InfoQ](https://www.infoq.com/news/2026/11/pinterest-intel-profiling/)，11 月）

  gProfiler 原本是 Granulate 开源的连续性能分析器，定位是编排层：把 perf、async-profiler、py-spy、eBPF 的输出合并成一张跨语言的火焰图。Pinterest 没有自建闭源平台，而是与英特尔一起扩展它并把能力回馈上游，新增动态分析（通过 UI 或 API 对某台主机、某个集群按需抓取）、硬件层遥测（缓存行为、内存带宽、CPU 停顿）和挂钟时间火焰图——CPU 占用不高但响应慢的服务，往往时间卡在 IO、锁或远程调用上，这类等待只有挂钟分析才看得见。

  工程细节值得抄：采集与分析分离，代理常驻但平时休眠，CPU 低于 1%、内存约 100 MB，靠心跳接指令，改采样频率与时长不用重新部署；数据落 S3，SQS 异步索引，ClickHouse 供查询，React 前端做火焰图交互。他们选 gProfiler 而不是改造 VTune 的理由也很实在：VTune 偏处理器级调优，不是云原生集群分析器。

- **[Zero C#：不要运行时、不要 GC，从 Linux 到 386](https://onurgumus.github.io/zero-csharp/index.html)**（项目文档，HN 11-22 讨论 160 分）

  它是 bflat 的一个分支，把 C# 直接编译成小型原生程序：没有 .NET 运行时，没有垃圾回收，目标机器上什么都不用装。语法、类型检查、泛型都保留，内存改为 arena——一次性分配、一次性释放，配套一个小库在 arena 上提供字符串、集合与输入输出。

  同一份源码能跑 Linux、macOS、Windows、WebAssembly，甚至通过 DOS 扩展器跑在 386 上；hello world 在 Windows 上是 11 KB、Linux 上 40 KB。缺的是运行时在程序运行期替你做的事：字符串不再自动回收，集合要显式指定生命周期，错误用 union 返回而不是异常。它更像一个关于"运行时到底提供了什么"的教学样本，MIT 许可；除非你在意启动时间与二进制体积，暂时没有理由把业务迁过去。

- **[Muru：mod_wsgi 作者用 Rust 重写 Python 应用服务器](https://simonwillison.net/2026/Nov/21/muru/)**（Simon Willison，11-21；[代码](https://github.com/muruhq/muru)）

  Graham Dumpleton 二十年前写了 mod_wsgi，现在用 Rust 做了 Muru，目标是把开发和生产放进同一个进程模型：import once / fork many、开发期自带 HTTPS、按 worker 上报的指标伸缩、缩到零、不重启即可发布、在容器里当更好的多租户租客、与 Kubernetes 协作而不是绕开它，最后是每页一个 toolbar 和 trace 面板。他从 11 月 4 日起把每一步设计写成公开记录，18 篇连着看是一条完整的工程叙事。

  项目还早，没有生产采用案例。他自己在那篇"AI as a lifestyle choice"里说得直白：表面上 AI 干了很多活，但"什么还不够好"仍由他判断。Python 部署层十几年没大变化，这套把开发体验和运维放进同一设计的思路值得跟。

- **[Upload2Shell：Ghostscript 字体加载器越狱，波及 WordPress、Roundcube、CUPS](https://pwn.ai/upload2shell)**（pwn.ai 研究，11-21 起公开案例）

  Type 1 字体加载器的 use-after-free（CVE-2026-125396）可以越过 Ghostscript 的 `-dSAFER` 沙箱、改掉原生路径控制并执行命令。麻烦的是攻击面：任何"上传后渲染"的链路都可能把文件送进 Ghostscript——WordPress core（Author 及以上，或被授予 upload_files 的 Contributor）、Roundcube 查看邮件时的缩略图、Plesk、Debian 13 的 CUPS（未认证的 IPP 任务以 lp 身份执行）、MediaWiki 的 PdfHandler，以及走 ImageMagick delegate 的一堆服务。

  修复其实早已发出：Ghostscript 10.08.0（9 月 8 日）、Ubuntu USN-8949-1、Debian 13 安全更新；CVE 编号 11 月 9 日分配，本次是案例研究陆续公开。工程结论不只"升级"：把渲染器当不可信代码跑——独立容器、断网、只读挂载、限制文件类型白名单，比只校验扩展名有用得多。
