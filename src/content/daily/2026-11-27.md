## 今日概览

截至今天 09:25（UTC+8），过去 24 小时最值得记的一件事是 Google 把 MCP 从「推荐封装」改成了「准入门槛」：11 月 24 日八个 Workspace MCP 服务器转正，同时 API 条款新增附录，明年 2 月 1 日起凡由 AI agent 驱动的工具都必须走这些服务器，直连 REST 只能拿标准级配额。这对所有做邮件、日历、文档集成的团队都是一次限期改造。

第二件事在人不在产品：Claude Code 的产品负责人 Cat Wu、桌面版创建者 Anthony Morris、核心工程师 Thariq Shihipar 相继确认加入 OpenAI，最后一位在 11 月 26 日正式官宣。Anthropic 股价 11 月 24 日首次收于 83 美元发行价之下，11 月 25 日小幅反弹到 82.79 美元。

工程侧今天很实在：Vite 8.4 把 dev server 的文件访问从黑名单改成可选白名单，`node:sqlite` 在 Node 27 alpha 里转正，还有一个把 PostgreSQL 打包成单个可执行文件的项目。

## 行业动态

- **[Google 新条款：明年 2 月起 AI agent 只能经官方 MCP 访问 Workspace](https://techstackups.com/articles/google-workspace-ai-agents-mcp/)**（Tech Stackups 报道，11-26；Google 公告与条款更新 11-24）

  11 月 24 日 Google 把八个 Workspace MCP 服务器转为正式可用，同时在 API 服务条款里加了「Workspace AI Tools Addendum」：从 2027 年 2 月 1 日起，任何「本身是、或由 AI Agent / AI Harness / AI 模型驱动」的 Workspace 访问工具，都必须通过 Google 的 MCP 服务器拿数据；刻意伪装成非 agent 来规避同样禁止。违规的后果写在条款里——限制或移除访问权限，直至停用账户。同一天起，agent 直接打 REST 只能拿到标准级配额，项目买了什么等级都不作数，非 AI 的定时备份、CRM 同步这类确定性脚本不受影响。

  接口能力并不齐。Gmail 服务器能搜邮件、读线程、建草稿、打标签、进回收站，但不能发信、回复、转发，也不能改已有草稿——这些工具「需要合作伙伴权限，尚未普遍开放」；Drive 缺移动、重命名、分享。真正会让产品团队疼的是数据条款：Workspace 数据只能用于「完成用户授权的活跃任务」，用户断开后必须删除，而 Google 对「Google 技术信息」——定义涵盖向量嵌入、记忆索引、用户画像、组织图谱——的保留上限是 30 天，且禁止用这些数据做训练、微调、评测和蒸馏。

  也就是说，那个「给我建一份收件箱长期索引、能回答去年合同问题」的助手，得按月重建索引或者砍掉这个功能。做 Gmail 或 Calendar agent 的话，这两个月里要决定的是：接 MCP、接受能力缺口，还是放弃这类集成。

- **[Ubuntu 对两个内核高危漏洞的修复延迟被公开质疑](https://www.openwall.com/lists/oss-security/2026/11/25/9)**（oss-security 邮件列表，11-25，Hanno Böck）

  帖子点了三个洞：Linux 内核 TCP 栈的远程内存破坏 NoisyTCP（CVE-2026-99288）11 月 16 日公开细节，九天后 Ubuntu 仍无修复；影响 AMD 虚拟化的 KVM 主机逃逸（CVE-2026-99312）11 月 18 日公开，同样没有；此前另一个远程 TCP 破坏（CVE-2026-98432）拖了数周才修。作者的说法是其他发行版在细节公开时就已经有了补丁，并引用了 GreyNoise 关于相关漏洞可能在野被利用的分析。

  这是一封公开质疑邮件，不是审计报告，Ubuntu 方面在帖子里没有回应。但它给出的判断标准值得借用：内核级远程内存破坏属于「几小时内该有更新」的类型，如果基础镜像的补丁窗口以周计，那就不是「LTS 稳定」而是「暴露窗口更长」。

- **[花 3 美元接管一个美国财政部子域](https://www.intruder.io/research/taking-over-us-treasury-subdomains-for-3-each)**（Intruder 研究，11-24 发布、11-26 更新）

  原理不新但依然有效：AWS 弹性 IP 释放后，DNS 里指向它的记录如果没删，任何人都能申请到同一个 IP，从而完整接管这个子域——可以拿来做钓鱼页、种 cookie、收邮件验证码。研究者只扫了不到 1% 的 IP 空间，就找到多个真实可接管的记录，其中包含美国财政部的域名，已通过漏洞赏金渠道上报，单价 3 美元一个。

  对自己有域名的人来说，可执行的部分很具体：迁移托管、下线服务、换 CDN 之后，把所有指向云 IP 的 A/AAAA 记录过一遍。静态站换托管最容易留下这类悬挂记录，因为站点本身没坏，只是那条 DNS 指向了一个已经不属于你的地址。

## 产品发布与更新

- **[Hub：用一句话管一百个 Claude Code / Codex 会话](https://www.producthunt.com/products/hub-20)**（Product Hunt，11-26，358 票）

  解决的问题是「十个会话就是一团乱麻」：哪个卡住了、哪个在等你确认，全靠人肉巡检。Hub 的做法是加一个协调者——你用自然语言在浏览器或 Telegram 里给它派活，它把任务分给执行会话，只把需要你决策的事推回来。每个 agent 可以单独指定模型，常规任务给便宜的、有风险的给大的；协调者会自己判断哪些属于哪类。

  免费、Apache-2.0、自托管，跑在自己的 Claude 或 ChatGPT 订阅上，不与两家官方有关联。笔记本合盖时任务暂停、开盖续跑，要通宵就装到小服务器上——`--server` 模式，4 GB 内存起步，页面从手机打开。团队可以共用一个 hub（把它的 Telegram bot 拉进群），也可以各跑各的、让 hub 之间互相发消息。

  作者自己把话说得很直白：这是实验品，agent 不会向你要许可，用之前先读仓库里的 SECURITY.md。所以它的实际定位是「把本机执行权交给一个调度器」，收益是并行吞吐，代价是权限边界。

- **[Bifura：用 AI 爬虫的视角看自己的网站](https://www.producthunt.com/products/bifura)**（Product Hunt，11-26，143 票）

  按 AI crawler 的抓取方式取回页面，给一个 agent readiness 分数，附 30/60/90 修复计划，还能在沙箱里试改再上线；同样的检查有 API，可以放进 CI 当发布前关卡。免费检查不需要注册，launch 价格到 12 月 3 日，优惠码 LAUNCH10。

  对个人站和文档站这是目前最省事的一类检查。有位评论者实测自己的站点拿了 71 分、10 个 AI 爬虫全部放开，但发现只有 47% 的文本在不执行 JavaScript 的情况下可读——这恰好是服务端渲染站点最容易忽略的退化。作者在评论里也承认短板：目前不校验结构化数据里的 sameAs 是否真的指向对应账号，已经排进路线图。

  需要注意它的评分体系是自家定义的，分数高低不等于模型真的会引用你；把它当「机器能读到多少正文」的诊断工具，比当排名工具更合适。

- **[Pax：把编码 agent 拆成一堆可替换插件](https://www.producthunt.com/products/pydantic)**（Product Hunt，11-26，118 票、7 条评价）

  Pydantic 官方出的终端编码 agent，卖点是「连写代码这件事都是插件」：`/plugins disable coder` 之后它就退化成普通聊天客户端。更有意思的是 `pax --agent my_agents:reviewer`——把你自己用 Pydantic AI 写的 agent 原样放进终端跑，带自己的工具和指令，不加载 Pax 的任何默认插件；同一个 Agent 对象还能继续在服务端使用。

  模型无关，`uvx` 一条命令就能试。对已经在 Python 侧写 agent 的人，这是目前最轻的「一份定义，既跑服务又跑终端」的路径；对只用 TypeScript 的人，价值主要在验证 agent 定义与运行环境解耦这个思路。

## AI 技术

- **[Mixture-of-Loops Transformer：拿 KV 当循环之间的记忆](https://arxiv.org/abs/2611.34923)**（arXiv 2611.34923，11-25 提交，ByteDance-Seed；HF 日榜 57 赞，代码在 [hustvl/MoLT](https://github.com/hustvl/MoLT)）

  循环 Transformer 的做法是让共享层跑多遍来提升表达力，代价是效率。这篇问的是一个更底层的问题：相邻循环之间到底该传什么？答案是拿 KV 当记忆，用 Mixture-of-Loops Attention 做跨深度、跨循环的选择性复用，并给出两个变体——MoLT-R 保留残差流、读本地 KV，换表达力；MoLT-KV 从 embedding 重新开始，读当前循环的 KV 加上前一轮在更早位置的记忆 KV，换效率。

  MoLT-KV 顺带消掉了「同一位置跨循环依赖」，配合 loop forcing 可以并行训练，并支持超出训练循环次数的单次遍历解码；U 形的 U-MoLT 再把记忆构建和预测读出分开，跳过用不到的解码遍历而不改变输出。

  数据是实的：400B token 预训练里，U-MoLT 在 700M / 1.5B dense 和 3B MoE 上全面优于 OLMo3，700M 上验证集交叉熵的 token 效率是 1.7 倍，3B MoE 的十域困惑度降 0.75、十任务准确率涨 2.1 个百分点；拿 Qwen3.5-0.8B-Base 做 100B token 继续预训练，11 个域全部下降，平均 token 效率 1.4 倍。推理侧在 S 规模（约 113M）上延迟 996.6ms，与非循环的 OLMo3 的 1000.6ms 基本持平。

  前天智谱的 GLM-5.4 把循环结构做进了产品，这篇则是把它做成可并行训练、可控制推理成本的通用结构，且给了代码。局限也清楚：最大只做到 3B MoE 的预训练，更大规模是否同样成立还得等。

- **[NVIDIA：让模型自己决定什么时候压缩上下文](https://arxiv.org/abs/2611.34147)**（arXiv 2611.34147，11-25，NVIDIA；HF 日榜 6 赞）

  现在的 agent harness 普遍替模型管上下文：窗口满了就触发一次 compaction，把历史总结掉。这篇研究的是另一种做法——给模型一个 context API，由它自己决定何时压缩、压缩什么，并在 NVIDIA 开源的 agent harness `nooa` 里实现，在 8K 到 512K 的预算下对比文档研究和机器学习工程两类任务。

  结果值得抄进自己的 harness：会用这个 API 的模型准确率更高，而且往往输入 token 更少，预算越紧差距越大——GPT 6.1 在 32K 预算下把 OfficeQA Pro v2 的分数从 21% 拉到 56%，接近三倍；Kimi 最多省 41% 的输入 token。

  但模型之间的差异极大：调用 API 的频率、压缩的力度、从多少 token 开始压缩，各家完全不同，改一句 prompt 就能改变时机。这说明「模型自己管上下文」目前还不是一个开箱能力，而是需要逐模型调的东西。

  最后一段对做推理引擎的人有直接价值：压缩之后后缀没变，复用这段的 KV cache 可以把每请求的 prefill 计算量最多砍掉 15%，精度无可测变化。也就是说模型侧的自管上下文和引擎侧的 KV cache 编辑要一起设计，单做一边拿不到全部收益。

- **[Notion 官方 MCP 被指在上下文里塞推销指令](https://news.ycombinator.com/item?id=50658093)**（Hacker News 讨论，11-26，46 分；原帖在 r/ClaudeCode，正文未能读取）

  帖子标题称，把 Notion 官方 MCP 接进 agent 之后，它的工具返回里夹带了引导用户升级付费方案的指令。原帖正文我打不开（Reddit 直连与页面抓取都失败），所以只能转述讨论：有人引用这段指令的措辞，说它要求 agent 在不告知用户的情况下把话题引向付费方案，并认为这等于「用用户的钱生成广告」；也有人觉得工具出错时提示升级本身可以接受，问题在于「工作已经顺利完成还推销」。另有评论提到 DoorDash 的 CLI 要求每次调用都带上用户原始请求。

  无论细节如何，这类事情暴露的面是真实的：第三方 MCP 的返回内容是模型会当指令读的文本，等于给外部服务开了一个写 prompt 的口子。接第三方 MCP 时的实际做法是把它的输出限制在子 agent 里、只把结论带回主上下文，并对工具返回做长度与来源的约束。

- **[AMD 专用 llama.cpp 分支：35 到 55 tok/s，以及「改模型怎么想」的代价](https://devnull.land/amd-specific-llama-cpp)**（devnull.land，11-26；HN 279 分）

  这篇的价值不在那个分支本身，而在它点出的一类现象。作者观察到 2026 年涌现出一批「单硬件、单模型」的专用推理引擎，很多是拿前沿模型直接写出来的，共同点是追更高的生成速度——而追到后来，优化不再是针对硬件，而是改变模型「怎么想」。他举的例子是 Strata：优先选已经加载在显存里的专家，即使按路由本该选被换到内存或磁盘上的那些。这在 benchmark 上表现为更快，代价是输出质量。

  他推荐的是另一种做法：`llama-cpp-rdna-boosts`，对固定 commit 的 llama.cpp 打一组最小补丁，不改变模型行为。在他自己的 AMD 卡上，生成从 35 tok/s 提到 55 tok/s，prefill 从 700 提到 1300 tok/s——单机单卡的单次实测，作者自己也标了 YMMV。

  判断一个「专用分支」值不值得用，可以看补丁碰了什么：只动 kernel、调度和内存布局的通常安全，动了路由、专家选择、量化策略的，就是在换模型。

## 大前端与后端

- **[Vite 8.4：dev server 文件访问改成可选白名单](https://vite.dev/blog/announcing-vite8-4)**（Vite 官方博客，11-26）

  `server.fs` 这个检查从 Vite 2.7 起就是黑名单模式——你得自己列出敏感文件，Vite 再补丁式地堵绕过。攻击面在增长，8.4 加了严格模式：`server.fs.strict: 'extended'` 把检查扩展到插件加载的模块，并把这些模块登记进白名单的路子从 `import` 扩到 CSS 的 `url()` 等引用方式；和 `server.fs.allow: []` 组合起来，就只服务入口可达（含传递引用）的文件。插件如果生成了非 import 方式引用的资源，要调 `this.environment.addSafeModule` 登记。官方计划在下个大版本默认启用。

  第二个变化跟浏览器规范走：HTML 规范今年 7 月更新，允许浏览器重试失败的动态 import 模块请求，Chrome 156+、Firefox 155+、Safari Technology Preview 252 已实现。Vite 8.4 相应改了 preload helper，重新执行动态 import 时会把该 chunk 的 CSS 一起重取——以前第一次请求失败，之后再点还是失败。

  其余几条偏日常：CSS 的 `url()` 现在支持 subpath imports（先按 subpath 解析，失败再回退成 hash URL），官方建议用它替代 `resolve.alias` 和 `tsconfig paths`，因为 Node.js 和 TypeScript 都认；检测到同一项目重复启动 dev server 会直接报错并给出 PID（`--bypass-lock` 可跳过）；支持 Wasm 的 source phase import，返回 `WebAssembly.Module`，等 TypeScript 7.1 稳定后会推荐用它替代 Vite 自己的 `.wasm?init`；SSR 的 bundled dev mode 还是高度实验状态。

- **[Node.js 27.0.0-alpha.0.2.0：`node:sqlite` 转正](https://nodejs.org/en/blog/release/v27.0.0-alpha.0.2.0)**（Node.js 官方，11-26）

  这条 alpha 里最该注意的是 `node:sqlite` 被标记为 stable——内置 SQLite 从实验特性变成了可以默认依赖的东西，同时补了 `statement.columnCount`、在没有 SQLite 支持时抛 `ERR_NO_SQLITE`。对一个只需要单文件数据库的服务，这意味着不必再引第三方驱动。

  同时有几条在做减法：`util.TextDecoder` 和 `util.TextEncoder` 弃用（改用全局同名对象）；TLS 重协商在文档层弃用，要显式 `allowRenegotiation` 才开；`--process-timeout` 从实验转为正式，输出里也包含 worker；`http2` 补了 `setHeaders`、informational header 的回调、compat response 的 `writeProcessing`；新增 `os.guessFileDescriptorType`。alpha 阶段还会有变动，但方向是清楚的：核心 API 收敛，机制性开关转正。

- **[minipg：把 PostgreSQL 做成一个可执行文件](https://progrium.github.io/minipg/)**（Jeff Lindsay，11-26；HN 288 分）

  一个 `.pgdb` 目录就是整个数据库——数据、配置、凭证、Postgres 版本都在里面，`minipg app.pgdb` 直接开一个 psql shell，`minipg run app.pgdb -- npm start` 会带好 `DATABASE_URL` 跑你的应用。服务在需要时启动、空闲时自己停。

  实现方式比用法更值得看：它内嵌 Docker Hub 的 `postgres:18-alpine` 镜像，用 Zig 写的 `h9` 当库，把一个 Plan 9 内核放进宿主 hypervisor 里直接应答 Alpine Postgres 二进制的系统调用——没有 Linux 内核要启动，没有 VM 镜像，也没有 Docker。CI 里这套尤其合适：Linux 二进制是静态的，不需要特权也不需要设备，没有 `/dev/kvm` 就走原生后端，一个测试作业可以短到两行。

  这是一个个人项目，作者自己也把它摆在演示和研究的位置，别往生产上放。但它说明了一件实用的事：在本地开发和 CI 里替掉「起个 Docker 跑数据库」这条路，已经不需要容器了。

- **[sqlite3_rsync：磁盘不够也能做快照备份](https://simonwillison.net/2026/Nov/26/sqlite3-rsync/)**（Simon Willison 博客，11-26）

  这个工具 2024 年 10 月随 SQLite 3.47.0 加入、2025 年 5 月在 3.50.0 增强，Simon 说自己这次才真正理解它最好用的地方：可以直接把数据库快照通过 SSH 推到另一台机器，不需要先在本地复制一份。常规做法里不管是 backup API 还是 `VACUUM INTO`，都得有足够空间放一份完整副本——小实例磁盘用过半就做不了备份。

  同步逻辑和 rsync 同源：副本端把页（或页组）的哈希发给源端，源端只回传不同的页，哈希不匹配时再要更细粒度的哈希。两端差异极大时，交换哈希的开销可能让总带宽略超整个库的大小，但超出部分只有几个百分点。顺带一提，Simon 自己在文末承认这功能 2024 年就写过一次，属于典型的重读旧笔记。
