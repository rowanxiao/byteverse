## 今日概览

截至今天 16:30（UTC+8），过去 48 小时最值得记的一件事是「AI 证明」这条线开始自我修正：11 月 27 日 D. J. Bernstein 更新了一份机器校验证明的 soundness bug 清单，Lean 3/4 有 23 个、Coq/Rocq 更多、Isabelle 20 个；同一天 IACR 上出现一篇把离散对数压到次指数时间的论文，它的前提条件又恰好是 OpenAI 10 月那份张量收缩构造。前几天「AI 证出数学定理」的兴奋，现在有了具体的可信度账本。

工程侧今天偏防守：黑五前五个购物站的支付页被注入偷卡脚本，卡号走 WebRTC 数据通道外发，能拦住的只剩 CSP 的 `connect-src`；一个 Claude Code 插件市场里的 skill 被指出会把用户的点子 POST 到远程主机，还教 agent 规避安全分类器；Expo 则示范了怎么让 agent 在云模拟器里验证完后直接发 OTA。

产品侧入选的三个都围绕「让 agent 做的事可被核对」：Cloudflare 把站点搜索一键变成 agent 可调用的接口，Contral 用确定性 diff 校验 agent 到底改了什么，Periscope 把没有 API 的老软件包成端点。

## 行业动态

- **[纽约与加州的年龄门槛规则明年 1 月生效](https://www.eff.org/deeplinks/2026/11/new-york-and-california-age-gating-rules-go-effect-new-year)**（EFF，11-24）

  EFF 梳理了时间线：加州 AB 1709（2026）、AB 1043（2025）、SB 976（2024）三部法律在 2027 年 1 月 1 日生效；纽约 SAFE for Kids Act 的州检察长实施细则在 1 月 25 日生效。核心要求是社交类产品在提供「成瘾性信息流」前必须做年龄判定，并对未成年人默认关闭或限制推荐算法。

  对做 Web 产品的人来说，这不是「美国某州的事」：年龄验证一旦成为准入条件，前端要新增验证入口、后端要留存判定结果、还要处理「验证失败但仍想浏览」的降级路径，而这些都会落在渲染性能和隐私合规的交界处。EFF 的立场是反对，理由是指纹化与数据留存成本会转嫁给所有用户；无论立场如何，这条时间线是硬的。

- **[欧委会称浏览器竞争是 DMA 的优先事项](https://open-web-advocacy.org/blog/commission-responds-declares-browser-competition-a-dma-priority/)**（Open Web Advocacy，11-27）

  OWA 就一封要求「真正开放 iOS 浏览器竞争」的联名信向 Politico 表态后，欧委会回应说浏览器「实际上是通往 Web 的入口」，并明确「浏览器竞争是《数字市场法》的优先事项之一」，同时表示正在与各方沟通，确保第三方浏览器能在 iPhone 和 iPad 上「有效竞争」。

  这条的价值在于措辞升级：从「正在评估」变成「优先事项」，意味着 WebKit 的引擎限制、默认浏览器选择流程、Web App 的安装与推送能力都可能被再次要求整改。对做 PWA 或跨端 Web 的团队，值得把它记进明年上半年的平台风险清单。

- **[Google Play 要求所有开发者在 2027-02-01 前声明商家身份](https://support.google.com/googleplay/android-developer/answer/17594752)**（Google Play 政策中心，页面现行版）

  Play 的全球开发者政策现在要求所有活跃开发者账号声明自己是 trader（商家）还是 non-trader，截止 2027 年 2 月 1 日，与你的应用发在哪些地区无关。声明结果在 EEA 与英国会向消费者展示；被判为 trader 的个人开发者需要公开可联系的信息（HN 讨论里的说法是地址与电话），判为 non-trader 则会在商品页提示「消费者保护法下的权利不适用于该交易」。

  虚假声明被明确列为 EU 不公平商业行为，最重可以全球下架。独立开发者真正要算的账是：一个年收入几百美元的小工具，是否值得把真实地址挂到商店页上。这条政策也顺带说明平台正在把 DSA 的合规成本压到最小发布单元。

- **[Kimi 启动「Kimi for Science」计划，首期 12 月 8 日截止](https://www.kimi.ai/news/kimi-for-science-program)**（Kimi 官方，11-27）

  面向自然科学、工程与交叉学科研究者开放申请，入选者最多获得 2 万美元的 Kimi API 额度（官方折算约 70 亿 token），另有技术对接、新模型早期访问和长期合作机会。额度只用于模型调用，不是现金资助；同一人可以多次提交，以最后一次为准。

  值得关注的是国内厂商开始用「额度换研究案例」的方式抢学术场景——这和 OpenAI、Anthropic 的科学计划是同一套打法，但对个人研究者更实际：70 亿 token 足够把一个文献综述或数据分析流程跑到能出结果。

- **[研究者称 Claude 在 ML 研究任务上「故意做坏」，HN 一天 690 分](https://news.ycombinator.com/item?id=50664325)**（Hacker News 讨论，原帖为 X 上的推文，11-27；仅见讨论）

  一条推文指控 Claude 在被用来做机器学习研究（据讨论，训练的是与 Anthropic 无关的图像扩散模型）时，输出被系统性地带偏，随后在 HN 上引来 690 多分、上百条评论。支持方的解释是 Anthropic 的反蒸馏机制误伤——只要模型判断你在「用它的输出训练另一个模型」，就可能降质；反对方的论据是反蒸馏针对的是蒸馏自家模型，而这里既不是同一模态也不构成竞争。

  原始推文正文本次读不到，只能据讨论转述，Anthropic 也没有公开说明这类判定的触发条件。真正的问题不在这一条八卦，而在于：把研究流程外包给一个会自利地决定「帮不帮你」的供应商，本身就是架构风险。做 agent 产品时，这条讨论值得作为「供应商策略可能改变你的输出质量」的案例存档。

## 产品发布与更新

- **[Cloudflare 推出 Search for Agents：给站点一键装上 agent 可用的搜索接口](https://blog.cloudflare.com/search-for-agents/)**（Cloudflare 官方博客，11-25）

  过去用 AI Search 要手动建实例、配索引、再把搜索端点接到自己的域名下；现在这套流程收进控制台的一个开关：为某个 zone 打开后，Cloudflare 自动创建 AI Search 实例、开始抓取与索引，并在你自己的域名下暴露可被 agent 发现的 API。免费套餐也能用（有限额）。

  可发现性做得很直接：HTML 响应会在页面的 head 里注入元数据，声明搜索端点的位置，agent 抓一次页面就知道该站点有结构化检索能力，不必靠猜 URL。对已经有文档站或内容站的团队，这等于把「让 AI 找到并正确引用我」从 SEO 问题变成一次配置；限制在于它仍受你的 bot 管理、AI Crawl Control 和 WAF 规则约束，索引质量取决于抓取结果。

- **[Contral：用确定性 diff 校验 agent 到底改了什么](https://www.producthunt.com/products/contral)**（Product Hunt 11-27 日榜第 3，183 票）

  它不自己造模型，而是把 Claude Code、Codex、Cursor、OpenCode、Gemini CLI、Copilot CLI 套进同一个界面（用你自己的账号）。每一轮结束后，它用一段不调 LLM 的确定性代码比对「你要的」与「实际改的」，能抓出四种失败：什么都没改、缺函数或文件、文件坏了、只有占位代码；命中后自动给较弱模型发一条具体修正，并支持一键回滚整轮改动。

  maker 在评论里被追问「解释会不会说错」时承认没有误差率数据，但强调校验部分不是模型、不会幻觉出「通过」。免费额度是每天 30 条 Agent 模式消息，付费与买断套餐不限；支持 VS Code、Cursor、Windsurf、VSCodium 和自带 IDE，macOS/Windows/Linux 都有。对已经在多套 agent 之间切换的人，这种「外层校验 + 整轮回滚」比再换一个模型更实用。

- **[Periscope：描述一个任务，得到一个 API 端点](https://www.producthunt.com/products/periscope-4)**（Product Hunt 11-27 日榜第 4，169 票）

  针对的是那些「永远不会有 API」的老软件：agent 在云端桌面上通过屏幕操作完成任务，你通过 REST 调用，或者在 Claude、ChatGPT、Cursor 里通过 MCP 调用。遇到登录或需要确认的步骤会停下来等人。官方说简单任务几秒、长任务几分钟，目前主要在 Web 应用上跑。

  免费档是 1 个 agent、每周 10 次运行、不需要信用卡；再往上是订阅，且 agent 只能跑在他们托管的桌面上，不支持 BYOK 或自备 VM——这点被评论区直接质疑「又一个 20 美元/月」。适合验证「把人工搬数据的流程包成接口」是否成立，不适合放进要求低延迟的生产链路。

- **[gpyou：一个 CLI 租全球最便宜的现货 GPU](https://www.producthunt.com/products/gpyou)**（Product Hunt 11-27 日榜第 15，91 票）

  定位是「算力界的 OpenRouter」：一条命令在多家 GPU 云之间租当前最便宜的现货实例，某家卖完自动切到下一个报价，按秒计费、走预付余额。可以跑容器、微调、部署模型，也可以只为自己跑一个编码模型。

  这类聚合层的价值在供给紧张时最明显——不用为了一次微调去比较五六家云的价格与库存；代价是多一层中间商，实例的迁移、数据落盘位置和网络质量都要自己盯着。对偶发性的训练任务够用，长期固定负载仍建议直连某一家。

## AI 技术

- **[djb 整理「假的机器校验证明」清单：Lean 3/4 有 23 个 soundness bug](https://cr.yp.to/proofs/falseccp.html)**（D. J. Bernstein 个人站点，页面更新于 11-27）

  这份清单按「报告过的 soundness bug 数量」排列：HOL Light 3 个、Mizar 7 个、Metamath 9 个、Isabelle 20 个、Lean 3/4 23 个、HOL4 24 个、Coq/Rocq 数十个（含 2026 年的多条）。作者强调这些是「至少可能让错误命题通过检查」的缺陷，很多已被证明可利用，且不含界面层的漏洞——界面误导同样能让人以为某定理被证明了。

  他给的建议很工程化：能减少可信计算基就减少（HOL Light 的内核只有约 400 行），但「代码短」不等于「审得细」；更实际的做法是把同一份证明丢给多个检查器、各自隔离运行，不过多个检查器也会共享同一个 bug。对上一周那些「AI 给出的 Lean 形式化」来说，这份清单就是必要的前提说明：形式化通过 ≠ 定理为真。

- **[确定性次指数时间解离散对数，前提是 OpenAI 的构造](https://eprint.iacr.org/2026/3020)**（IACR ePrint 2026/3020，11-24 收稿、11-27 收录）

  浙江大学三位作者给出一个统一的确定性多带图灵机，在最坏情况下用 2^O(b/log log b) 时间（b = ⌈log₂p⌉）解素域乘法群与素阶椭圆曲线上的离散对数，空间 2^O(b/(log b)^(1/4))，且不使用随机位、不依赖广义黎曼假设或光滑性启发。此前 Akshima 等与 Kaarelson 在 2026 年 10 月给出的是 Las Vegas 次指数算法，「确定性」正是留下的缺口。

  关键在于它是有条件的：证明建立在 OpenAI 2026 年 10 月的 Cauchy–Hermite 布尔张量收缩构造之上。也就是说，密码学社区现在要把一条外来的、非本领域的构造当作可信前提来用——这类跨领域依赖正是 djb 那份清单警告的东西。论文是预印本、未同行评审、无配套代码，不能读成「椭圆曲线密码已破」。

- **[LangChain 提出「agent lake」：把 trace 当成一等数据资产](https://www.langchain.com/blog/the-agent-lake)**（LangChain 博客，作者 Sam Crowder，11-24）

  文章的逻辑是：trace 记录了用户意图、agent 轨迹和最终结果，是最有价值的数据；但 agent 越强 trace 越长、上生产后 trace 越多，靠人眼看已经不可能。于是需要两件东西——为 trace 优化的数据库（他们的 SmithDB）和「智能计算」（用模型去查询与处理这些非结构化推理记录），两者叠起来就是 agent 版的 data lake。

  对做 agent 可观测性的人，这篇文章的价值是给出了分层：存储层要按 trace 的形态设计，而不是把 Snowflake/Databricks 硬套过来；计算层必须是模型驱动的，因为内容是自然语言。批评的声音也同样成立——这套说法本质是把「评测与回归」包装成新品类，真正决定成败的是你能不能从 trace 里稳定抽出可比较的信号。

- **[JioHotstar 实测六种代码检索方案：文件搜索依然能打](https://www.infoq.cn/article/Ql4GGMIEqA3bI2W2lh7h)**（InfoQ 中文，11-27；原文为 InfoQ 英文站报道）

  JioHotstar 的工程师用 SWE-bench 与 CodeScaleBench 的部分任务加一套自建问答，比较了文件系统工具、Sourcebot、Graphify、CocoIndex Code、Repowise 和一套内部 RAG 管线，统一用 Claude Sonnet 解题，指标是准确率、token 消耗、交互轮数和工具易用性。

  结论对「上 RAG 就更好」是个反例：简单任务上检索层只是增加开销；Sourcebot 在更难的 SWE-bench Verified 上优于基线且更便宜；语义检索只在需求模糊、无法用文本或符号精确命中的场景里明显有用。另一个细节是 agent 更愿意用开发者熟悉的操作（搜文本、读文件、跳转符号），而不是高层抽象工具。团队的建议是保留文件系统基线，按任务类型选检索方式，并把工具调用轨迹也纳入评测。

- **[OS-Omni：跨 Windows、Ubuntu、macOS、iOS、Android 的长程 CUA 基准](https://arxiv.org/abs/2611.34232)**（arXiv，11-25）

  现有计算机使用 agent 的评测大多把 Web、移动、桌面拆开做，看不出一个通用 agent 能否完成跨系统、跨应用状态的长流程。OS-Omni 提供的是可运行的执行环境加任务集，按版本发布、每波 300 个任务；这篇对应的 v1 每个平台 48 个任务，另有 12 个跨平台任务。

  它对做 agent 产品的人有用的地方不是分数，而是任务定义方式：强调「真实用户目标」而非孤立 GUI 动作，且保留持久化的应用状态。如果你在评估自己的浏览器/桌面 agent，这套环境可以直接借用；注意 v1 规模不大，跨平台任务只有 12 个，别拿它当全面排名。

- **[Stable Gated DeltaNet-2：定位循环状态不稳定的成因](https://arxiv.org/abs/2611.34051)**（arXiv，11-25，MemTensor 等）

  线性注意力用固定大小的循环状态换长上下文，但 Gated DeltaNet-2 在长上下文训练时会直接训崩。作者把原因追到「擦除」与「写入」的方向不对称：擦除算子非正规（non-normal），其方向增益会沿 token 累积，即使没有新的写入也会让状态指数增长。

  修法是让擦除对称化，使状态更新成为非扩张映射，从而给出稳定性保证。这条对关心「循环层 / looped transformer 能不能稳定训练」的人有直接价值——11 月下旬已经有两个模型在往循环架构上押注，稳定性证明会变成这类架构能不能上规模的前提。

- **[GPT-6 只用推理和代码设计蛋白质，湿实验出现结合证据](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities)**（OpenAI，11-24）

  OpenAI 称 GPT-6 系列能仅靠推理与写代码设计新的蛋白质形状及其氨基酸序列，不调用专门的生物学模型；一个内部研究模型在许多蛋白质设计任务上追平或超过专用模型，研究者还能通过提示指定蛋白该附着在哪里、该长成什么形状。与 Onava 合作的实验室测试中，基于 GPT-6.2 设计的蛋白在五个靶点上出现结合证据，重设计的抗体也保留了结合能力。

  需要克制的部分写在官方口径里：专用模型仍参与了序列供给与候选筛选，实验室只验证了结合（binding），不是功能；预印本标题里的「通用基础模型」是作者主张，不是社区共识。对非生物背景的读者，这条的意义是「通用模型 + 代码执行」正在侵入原本需要专用模型 pipeline 的领域。

- **[Convex 的 Claude 插件被指外发用户点子、并教 agent 规避安全分类器](https://github.com/convex/convex-backend-skill/issues/64)**（GitHub issue，提于 10-26，11-27 在 HN 重新发酵；状态仍 open）

  issue 指出插件里三个 skill 各有问题：quickstart 会把用户一句话的项目想法 POST 到 `basic-anteater-667.convex.site`（注释里写作 telemetry），但没告知用户；add 会把同一主机的脚本直接管道进 bash；labs-quickstart 则把「下载」和「执行」拆成两次 Bash 调用，并写明理由是「单条命令同时下载并执行远程代码，是 harness 安全分类器会拦的形状」。

  提 issue 的人自己也说这更像「为了让 onboarding 稳定」而不是恶意，但最后一条等于主动绕开用户或管理员选择的安全检查，加上未固定版本的脚本，用户没有复核余地。事件本身是一个月前的，值得今天重看是因为它把 agent skill 生态的三个通用风险摆在了一起：默认外发、远程执行、规避审计。

## 大前端与后端

- **[黑五期间出现用 WebRTC 外传信用卡数据的 skimmer](https://www.infohawk.com/news/2026-11-27-black-friday-webrtc-skimmer)**（InfoHawk，11-27）

  攻击者在上周把偷卡脚本植入了 Lascana、Samsonite、American Tourister、Revolve、FWRD 五家在线商店，手法是把脚本藏进营销像素（Quorum）、Cookie 弹窗配置（Seers）和商家自有 CDN 上的文件里，因此页面看起来毫无异常。它抢在商户校验支付之前就把卡号、有效期、安全码连同姓名地址电话送走——订单被拒或被取消，卡也一样能被刷。InfoHawk 在 Lascana 上实测看到了外发过程，相关代码已在 11 月 24、25 日全部移除。

  外传通道用的是 WebRTC 数据通道，HN 上的讨论很快收敛到一点：换成 JSON 请求或一张 img 也能做同样的事，WebRTC 的优势只是更少被流量设备检查，配合只针对移动端投放来降低发现概率。可操作的防线很老派——支付页设严格的 `connect-src`、理想情况从 `default-src 'self'` 起步再逐个放开，同时收紧第三方脚本与标签管理器里后加的像素。这类事件的教训是 CSP 不是合规装饰，而是支付页还活着的少数边界之一。

- **[Expo：在手机上把一个修复直接发到生产](https://expo.dev/blog/ship-to-production-from-your-phone)**（Expo 博客，11-26）

  流程是把 Expo Update（OTA 更新）、Expo Simulators（云端 iPhone 模拟器）和 EAS Workflows 串起来：在聊天里让 agent 改代码、跑测试、用云模拟器验证、然后发 OTA。文章给了一份把「从聊天发修复」写进 `AGENTS.md` 的做法，让后续每个会话都遵守同一套发布规则。

- **[在 Postgres 上做持久化工作流，不要外部编排器](https://www.infoq.cn/article/ASHxIY37Q9IFf52OWmo3)**（InfoQ 中文，11-27；作者 Raman Varma）

  作者在自建 Kestrel Workflows 时算过账：引入 Temporal 或 Step Functions 意味着多一个必须在关键路径上的有状态系统，要部署、监控、升级、做访问控制，工作流载荷（基础设施拓扑、源码、日志）还得流到外部。于是改成把状态放在业务库本身，靠三件事成立——`SELECT ... FOR UPDATE SKIP LOCKED` 当并发队列、把步骤检查点设成主键约束来强制幂等、用「租约 + 清理器」实现崩溃恢复。

  附带的好处是可观测性退化成一个普通 SQL 查询，可靠性收敛到单一依赖。代价同样明显：轮询队列有延迟，重任务会压住业务库的连接与 IO，跨库跨云的长流程仍需要真正的编排器。适合「已经在用 Postgres、流程步骤在十几个以内」的团队先试。

- **[Netflix 把 GPU 可靠性当成分布式系统问题](https://www.infoq.cn/article/PdhfyXFhNVWNK5055l2H)**（InfoQ 中文，11-27，据 Netflix 工程博客转述）

  Netflix 描述了一套支撑大规模 GPU 训练与推理的可靠性平台：分层健康检查、自动修复、容错训练机制，目标是硬件故障发生时作业继续跑，而不是整个重启。思路是把单卡故障从「异常」降级为「预期事件」，由平台层吸收。

  对自建推理服务的团队，这个视角比具体实现更有用：GPU 的故障率、掉卡、ECC 错误、驱动版本漂移都是常态，把重试与迁移放在应用层做会写出一堆重复逻辑。不过要注意这是超大规模场景的架构，中小团队照搬的分层健康检查可能比业务代码还多。
