## 今日概览

截至今天 12:30（UTC+8），过去 48 小时的主线是「代理开始接管真实世界里的动作」——付款、点按钮、跑命令——于是配套的信任机制一起被推到台前。

OpenAI 上线 ChatGPT Wallet，把银行卡换成支付网络签发的令牌，每笔交易都要生物识别批准；同一天前后，Google 的 Project Zero 宣布把零日披露窗口从 90 天一步步压到 30 天，理由是 AI 让「从补丁反推利用」的时间趋近于零。

工程侧两条更实用：Cloudflare 把跑在 Workers 上的浏览器引擎 Kitesurf 以 Apache 2.0 开源，代理浏览器可以自己部署；llama.cpp 与 ggml 同时发布 1.0.0，承诺稳定 API。另外有一份针对 15.9 万个 Lovable 站点的扫描，把 Supabase 默认配置的数据暴露规模摆上了台面。

## 行业动态

- **[Project Zero 改披露政策：90 天、60 天、30 天三步走](https://projectzero.google/2026/11/disclosure-policy.html)**（Google Project Zero，11-13）

  自 2021 年沿用的「90 + 30」被废除，改为「Full 90」：漏洞在报告给厂商 90 天后即公开，不再有 30 天补丁铺开期。2027 年 2 月 2 日缩到 60 天，2028 年 1 月 3 日缩到 30 天。宽限期（grace period）与变体策略（variant policy）一并取消，只保留极少数例外。

  理由写得很直接：LLM 让攻击者找洞、写利用的速度大幅提升，多个团队（包括恶意方）撞上同一个洞的概率也在上升；同时补丁一旦发布，攻击者反推细节的时间被压到接近零，所谓「补丁静默期」已经失去意义。文中还提到报告量级的变化——过去一年才找到几个洞的目标，现在每周能找到几个，需要厂商协商判断「是否修好」的流程已经难以维持。

  对做产品的人，这意味着安全响应窗口在系统性收紧：能自动化的升级与灰度要提前建好，靠人工排期消化高危漏洞的空间越来越小。Project Zero 也承认政策偏激进，所以选择三步过渡而不是一刀切。

- **[WSJ 称英伟达靠投资 AI 初创制造 GPU 紧缺](https://www.techpowerup.com/354814/nvidia-allegedly-engineered-scarcity-by-funding-ai-startups-to-buy-its-gpus)**（TechPowerUp 转述 WSJ，11-14；付费墙，据转述）

  报道称，英伟达一边向小型 AI 初创与新型云厂商投资，一边指望这些公司拿钱回头买自家 GPU、建数据中心，用这种方式消化从台积电拉来的超额产能，同时维持「供不应求」的市场观感。文中援引 8 月的一次财务会议：CFO（现代理 CEO）Colette Kress 主张收缩这类循环融资安排，也质疑被投的小型云厂商根本买不起卡。

  需要分清性质：这是媒体基于匿名信源的指控，公开报道里没有可独立核验的账目，也没有监管调查结论。它的价值在于给出一个观察框架——当一家公司同时是供应商和股东时，它披露的「需求」需要打折看。对采购方来说，短期含义是 GPU 与内存的报价仍会剧烈波动，长约与现货的价差值得盯紧。

- **[15.9 万个 Lovable 站点被扫：大量 Supabase 数据无需登录即可读](https://www.crissyfield.de/research/lovable-en/)**（crissyfield.de 研究，11-14 起在 HN 讨论；德文首发 11-02 于 Handelsblatt）

  研究者从 Common Crawl 里取出 2025 年 12 月至 2026 年 9 月的 159,041 个 Lovable 项目，其中 34,545 个接了 Supabase，24,664 个在页面加载时就把数据库记录发到前端。再用同一把 anon key 发只读请求，在 7,403 个站点的 10,560 张表里读到了邮箱字段。

  后果是具体的：一个德国生活方式论坛暴露了 8 万多个含真实姓名、邮箱、生日、性别的用户档案，外加 20 多万条聊天记录；若干活动主办方与餐厅把票务、餐饮记录连同电话、地址、支付信息、票码一起留在公开可读的表里；还有物业公司把 AI 生成的内部邮件摘要暴露在外。

  作者自己划了边界：样本来自 Common Crawl、不代表全部 Lovable 应用，「30%」不是泄漏率，只说明在被细查的那 24,664 个站里有这个比例能读到邮箱。真正可复用的是结论——用 AI 一键生成的后端，默认 key 加没开 RLS 就是公开数据库；上线前至少检查一遍 Supabase 的 RLS 策略和 anon key 能碰到哪些表。

## 产品发布与更新

- **[ChatGPT Wallet：把支付令牌交给智能体](https://openai.com/index/introducing-chatgpt-wallet/)**（OpenAI，11-13）

  用户一次性绑卡，之后每笔购买由支付网络生成令牌（替代卡号、安全码、有效期），商家和模型都拿不到真实卡信息，原有卡片的返现与拒付保护照旧。流程是：先确认商品、金额、用哪张卡，再用 Face ID 或指纹批准，每次批准留一条授权记录。

  可用范围很窄：仅美国、仅 ChatGPT Pro 订阅用户、需 18 岁以上与美国发行的合格卡片，初期只从 dots 入口灰度。官方也承认两类失败——部分站点或支付系统会误拦这类购买，风控系统可能把合法代理交易判成欺诈。

  给商家侧的配套是另一份重点：在 ChatGPT 里认领企业并上传价格库存、用 Web Bot Auth 识别代理签名请求、用 WebMCP 暴露购物车等工具，风控伙伴列了 Forter、Riskified、Sardine、Signifyd，支付侧是 Adyen、Checkout.com、Stripe。换句话说，这不只是一个钱包，是一套「让网站对代理可编程」的规范草案。做电商或 SaaS 结算的，值得先读商家那部分。

- **[Kokonut UI：把组件库做成代理的安装源](https://www.producthunt.com/products/kokonut-ui)**（Product Hunt 今日榜第 8，11-14，91 票）

  100 多个 MIT 许可的 React 组件，走 shadcn registry，执行 `npx shadcn@latest mcp init --client claude` 后，Claude Code、Cursor、VS Code、Codex 可以直接搜索并安装组件到仓库；每个文档页同时提供 Markdown 版本，另有一个 rules 文件要求代理先查库再造轮子。

  这一版新增 65 个、重写 34 个，重点在代理界面：工具调用折叠成一行、工具批准卡片、diff 审阅、行内引用、上下文用量条，以及嵌在回复里的结账流程。代码以源码形式落进项目，无账号、无锁定。

  代价也要说清：组件是复制进来的，后续升级得自己跟；样式依赖 Tailwind 与 shadcn 生态，不熟这套的团队上手成本不低。如果你正在写 agent 聊天界面，tool approval 与 diff review 这两块是最容易返工的部分，先照抄再改是合理选择。

- **[Antelog：在代理跑命令之前拦一道](https://www.producthunt.com/products/antelog)**（Product Hunt 今日榜第 10，11-15，88 票；官网显示 11-10 首发）

  单条命令装完后，它接管 Claude Code、Cursor、Codex 的每一次命令执行：命中规则的直接在本地毫秒级拦下——对 home 目录 `rm -rf`、`DROP TABLE`、强推 main、删云数据库或卷、读 `.env`；规则没覆盖但会改状态的动作，再去云端做一次 AI 判定，通常多花约一秒。失败时默认拦截，代理无法自己关掉或卸载它。

  免费版就能拦截，Pro 每月 25 美元（年付 199），Team 版加多人共享规则与审计日志；支持 macOS、Linux、Windows。代码闭源，这点与它的定位有张力：你是在把命令级别的否决权交给一个不可审计的二进制。

  边界同样明确：管不到你自己敲的命令，也不覆盖 Claude Code、Cursor、Codex 之外的代理（除非对方主动调 `antelog check`）；MCP 侧只拦数据库、云、git 服务器的删除类调用，其他工具仅记录；规则没命中、AI 也判为安全的破坏性动作会被放行。

## AI 技术

- **[llama.cpp 与 ggml 一起发 1.0.0，承诺 API 稳定](https://huggingface.co/blog/ggml-org/llama-cpp-v1)**（Hugging Face Blog，11-13）

  两个库同时进入 1.0.0：`libllama` 与 `libggml`。真正的变化不是功能，是契约——今后 API/ABI 的不兼容只在主版本号上体现，下游集成方可以据此安排升级节奏。项目已跑了三年半，大量应用直接依赖这两个库的接口，这一步是把「能跑」变成「可依赖」。

  现状数据：支持 150 多种模型架构变体与主流投机解码方法，后端可按需编译成动态库、运行时加载。CI 规模也扩了，借助 HF Buckets 与 HF Jobs 给 master 上每次合并做正确性验证，自建 runner 覆盖 NVIDIA、AMD、Qualcomm、Arm、IBM、Intel 的硬件。

  顺带一条社区反馈值得记：有人指出 prefill（长提示处理）仍是短板。如果你在做本地推理产品，稳定 ABI 是好事，性能评估还是要按自己的提示长度分布来做，别照搬短提示的跑分。

- **[600 次实验后，JEPA 世界模型的瓶颈不在预测](https://haddyalchaer.com/jepa)**（haddyalchaer.com，11-13）

  作者拿 LeCun 团队今年的 LeWM（基准是 Push-T：机械臂把 T 形块推到目标位）做了 600 次实验。第一个实验就把常见假设推翻了：把学出来的预测器换成模拟器的完美物理，长程任务成功率是 77%，原模型是 78%——在训练分布内的路径上，它的预测已经和完美物理等价。

  于是他转向「怎么用」：不重训模型，靠四个新的规划方法，把长程任务成功率从 22% 拉到 85%，接近直接喂专家子目标的水平（原文提到的一个细节是，目标图里某处像素的处理方式，对成功率的影响比换掉预测器还大）。

  需要保留的边界：Push-T 是单一仿真任务，作者是个人研究者，结论不能外推到真实机器人或通用世界模型。但对做 Agent 的人有迁移价值——当「感知/预测」足够好时，收益来自搜索与规划这一层，而不是继续堆模型。

- **[GLM-5.3 的双机部署实录：607.8 tok/s 的峰值与它的代价](https://developer.nvidia.com/blog/when-one-gpu-isnt-enough-serving-glm-5-3-across-two-nvidia-dgx-stations-with-vllm/)**（NVIDIA Developer Blog，11-13）

  GLM-5.3 的 NVFP4 量化版是 753B 参数的 MoE、每 token 激活 40B，权重约需 464GB 显存，超过单张 GB300 的 252GB HBM3e，于是用两台 DGX Station 通过 ConnectX-8 RDMA 互联、TP=2 切分，对外仍是一个 OpenAI 兼容端点。vLLM 侧开了多 token 预测、FP8 KV cache 与前缀缓存。

  数据很具体：在 SPEED-Bench Coding 上，并发 16 时输出吞吐峰值 607.8 tok/s；并发升到 32 反而掉到 385.0 tok/s，平均请求延迟 453.5 秒。这说明这套配置适合少并发、长输出的批处理，不适合当高并发在线服务——扩容要加机器，不是调参。

  对自建推理的团队，价值在于「两台中端机器拼一个大模型」这条路径被官方跑通了，带宽与显存是唯二的硬门槛。

- **[XYBench：考模型会不会纠正你的错误前提](https://huggingface.co/blog/allenai/xybench)**（Hugging Face Blog / Ai2，11-13）

  8,115 道题，全部来自真实的 XY 问题——用户想达成 X，却认定方案 Y 可行，于是只问 Y（经典例子：奶油挂不住，真正原因是蛋糕还热着）。题目构成是 Stack Overflow 1,557 条、Stack Exchange 184 条、人工整理 102 条、WikiHow 生成的 6,272 条；该工作在 EMNLP 2026 拿了 Best Resource Paper。

  测了 Claude Sonnet 4.6、GPT-5、Gemini 3.1 Pro、Qwen3.5-9B、DeepSeek-V4 Pro：五个模型大多能把用户问的那步做对，但很少把用户从错误路径上拉回来、指向真正目标；人类参考答案在这点上明显更强。

  对做 AI 产品的人是提醒：如果你的场景里用户不懂技术（客服、内部工具、数据分析），「照做」反而是失败模式，提示词与评测集里要显式奖励「先质疑前提」。

## 大前端与后端

- **[Cloudflare 把浏览器引擎 Kitesurf 开源，Apache 2.0](https://blog.cloudflare.com/kitesurf-open-source/)**（Cloudflare Blog，11-13；仓库 [cloudflare/kitesurf](https://github.com/cloudflare/kitesurf)，约 1.3k star）

  它把「代理用的浏览器」做成了无状态服务：跑在 Workers 上，自己解析 HTML、应用 CSS、执行页面 JavaScript、渲染截图，不需要 Chromium 容器。对外暴露 Chrome DevTools Protocol，Puppeteer 可以直接 `connect` 到 `ws://127.0.0.1:8787/devtools/browser`，代理通过 CDP 拿到完整控制权。

  结构分三块：Engine 管理会话与客户端连接，PageScript 跑页面与其 JS，PageRenderer 负责绘制；底层是编译到 Wasm 的 Rust 包。官方给的定位是比 Chromium 省 CPU 与内存、按需在全球网络上伸缩。

  自己部署要注意：需要 Workers Paid 套餐（依赖 Dynamic Workers 为每个页面起隔离 Worker），首次构建要先编译 Rust 核心。另外仓库描述仍写「experimental」，生产用之前先压测目标站点的兼容性——CSS 与 JS 覆盖面不会和真浏览器完全一致。

- **[Vercel Sandbox 在非 iad1 区域启动快 4 倍](https://vercel.com/changelog/vercel-sandbox-starts-up-to-four-times-faster)**（Vercel Changelog，11-13）

  关键在区域缓存：镜像数据从本地缓存读取时，华盛顿特区（iad1）以外区域的沙箱启动最多快 4 倍。对「每个代理一次任务、一个沙箱」的用法，冷启动时间往往就是用户感知的等待时间，这条改动的收益比单纯加 CPU 大。

  附带一个迁移信号：如果你的沙箱逻辑写死了 iad1 以换取启动速度，现在可以考虑就近部署，把延迟和启动时间一起降下来。

- **[Vercel Token Pass 月度额度从 80 提到 150 美元](https://vercel.com/changelog/vercel-token-pass-now-includes-one-hundred-fifty-dollars-of-monthly-tokens)**（Vercel Changelog，11-13）

  价格不变，仍是每团队每月 30 美元，可用额度翻近一倍，覆盖 AI Gateway 上的 featured 开源权重模型。这是把「开源模型价格战」直接传导到开发者账单上的一步。

  使用时留意两点：额度只对指定模型生效，闭源旗舰不在范围内；额度过期不结转到下月，实验性负载集中在月初跑更划算。

- **[Cloudflare 上线 Spend Management：到额度就自动停](https://blog.cloudflare.com/spend-management/)**（Cloudflare Blog，11-13，Beta）

  Pay-as-you-go 客户可以为产品设消费上限与多档告警阈值，触顶后 Cloudflare 直接暂停该产品，而不只是发邮件。首发覆盖 Workers 与 Durable Objects，可与 AI Gateway 的按用户、按模型预算配合，把「算力 + 推理」两类成本一起管住。

  这类功能对代理类应用意义更大：一次循环失控可能在一夜之间烧掉预算，硬停比告警有用。现在是 Beta，建议先在非核心账号上验证暂停后的恢复行为。

- **[给终端画真正的细线：不占格子的 cell border](https://www.joshka.net/cell-borders/)**（joshka.net，11-13）

  Ratatui 维护者的观察：TUI 长得都差不多，因为边框必须占字符格，一个面板四周就吃掉一行一列。他的方案是把边框做成终端协议——在单元格边缘绘制细线，而不是塞进格子；已在 Ghostty 上做成补丁（更早的版本在 Rio 里），并用 Ratatui 写了演示应用。

  效果差异可以用数字说明：没有该协议时回退到 box-drawing 字符，每个面板四周各损失一行一列，日志面板直接少显示两行。文中明确写了「本文与代码大量借助 AI 完成」，也在征求终端与 TUI 作者的意见。

  这是典型的「协议先行」提案：在 Ghostty 一家落地之后，还需要终端模拟器与库的协同。对做 CLI 工具的人，值得关注的是这条思路——把布局信息交给渲染层，而不是让字符编码去承担图形职责。
